# 基座与插件导航层级 · 原生实窗记录

2026-11-09。关联 C-07/C-11/C-12/C-16、F-UX-01/02、F-EXT-01/04/06、M-1 P01/P02；依据用户对重复侧栏开关与插件下钻辨识的纠正。设计见[导航层级与返回](../../../../docs/design/navigation-hierarchy.md)，源码与复现见[native-workbench](../../native-workbench/README.md)。

## 实际结果

| 场景 | 观察结果 | 范围 |
| --- | --- | --- |
| 一个导航区 | 空间入口与当前工作区内容使用同一个248pt位置，范围切换不改变当前对象；区域内部无重复收起开关 | 1280×820、900×680实窗 |
| 文稿与折叠 | 顶部保留QUSOR、产品设计、文稿及插件标识；折叠只改变内容宽度，当前标签与输入不变 | 宽/紧凑、浅/深色 |
| 对象与提供者 | 文稿/画布标签切换后，顶部提供者同步改变；导航范围切换保留当前画布 | 窗口内fixture |
| 插件整体进入 | 从画布进入阅读，宿主导航/对象标签退出，阅读自有书库与工具进入；具名宿主返回持续可达 | 最终宽窗工件 |
| 两级返回 | 正文中“书架”返回只回书库；宿主“返回产品设计”仍指向进入前工作区 | 最终紧凑工件；宽窗首轮也观察 |
| 来源布局恢复 | 返回原画布后恢复空间导航范围、展开偏好与信息面板；再回文稿验收文本仍完整 | 最终宽窗工件 |
| 功能目录来源 | 隐藏导航的功能目录进入插件后，宿主显示“返回功能”；返回仍是功能目录且导航保持隐藏 | 最终宽窗工件 |
| 紧凑书库导航 | “书库导航”进入独立导航页，“书架”返回集合；正文保留阅读身份与两级返回 | 最终900×680工件 |
| 宿主菜单 | 插件中选择“功能样例”实际离开插件，进入宿主功能目录 | 最终紧凑工件 |
| 搜索 | 打开后焦点在搜索输入，AX背景隔离；粘贴“画布”后仅一个结果，回车进入画布并更新提供者 | 最终紧凑工件 |
| 视觉与输入 | 浅/深色路径和插件标识可读；中文验收文字经原生粘贴，折叠、对象切换与插件往返后逐字一致，已恢复默认样文 | 实窗观察，不是读屏或IME资格 |

以上通过条件在窗口内样例范围成立；具体验收对应NAV-01–06及NAV-07已执行子项。截图和AX由CUA现场读取并在聊天中展示，本目录仅保存实际观察和hash，没有用绘制图片冒充原生截图。

## 限制与已保留问题

- `Entry.provider`、`PluginWorkspace`仍是普通TSX fixture目录；没有安装包、公开SDK装配、运行隔离、授权或真实组件替换。
- 输入只留在当前窗口；返回恢复对象与已记录的布局字段，不承诺滚动位置、焦点、应用重开或Core持久保存。NAV-08未执行。
- 早期自动化`typeText`尝试没有形成可见文字；改用原生粘贴并独立读取AX完成输入验收。没有将该结果记为中文键入/IME通过；既有native.log中还有IMK mach-port诊断，未在本切片归因或修复。
- 未验完整键盘/读屏、动态字号、大量对象、提供者缺失/崩溃、真实资源释放ACK或其他五端。旧[工作区组合报告](../native-workspace-composition/README.md)只代表其旧工件。

## 复现

```sh
python3 experiments/nsh-reader/native-workbench/prepare.py --size 1280x820
python3 experiments/nsh-reader/native-workbench/prepare.py --size 900x680
```

每次准备后打开输出的`.app`；已有窗口仍运行旧bundle时先关闭研究窗口再打开新工件。脚本本身只准备，不自动启动；最终保留1280×820浅色文稿与一个导航区供继续评审。源检查为NSH bundle构建、文档本地链接与diff空白检查；生产Rust没有改动，不用无关Core回归替代本次UI验收。
