# 保存想法列表实窗增量

日期：2026-11-10。关联 F-NOTE-01、F-SRC-01、F-READ-03、F-DATA-01、C-09/C-12。本轮是原生阅读工作区中的只读想法索引，不是正式 notes 功能包，也不代表完整回源旅程已经交付。

## 实现范围

- `learning-application` 增加按 vault 隔离、可按 document 过滤、按提交序号倒序的 PDF 想法查询。
- 列表只返回每条引文和想法的 512 UTF-8 bytes 有界预览、原始 byte 数与截断标记；完整内容仍只在 Core，查询不改写知识。
- 单次查询上限 200 条，空 vault 与越界 limit 明确拒绝。
- 现有原生阅读工作区新增“想法”视图，显示资料标题、页码、原文引文和用户想法，并区分当前资料可定位与需先打开其他资料。
- 想法列表在打开或手动刷新时读取 Core；列表仍通过普通签名 reader/editor 与 Core 的既有链路工作。

## 实际验证

| 范围 | 结果 |
|---|---|
| 应用层单测 | 3 项通过：倒序/库与文档隔离、UTF-8 有界预览、参数边界 |

| macOS 实窗 | AppKit 窗口打开已有 Core 数据后，“想法”视图真实列出两条旧中文想法；截图为 [notes-list.png](notes-list.png) |
| 截图指纹 | `sha256 e660d7628086d58e8d8e332520bc0c97b28a158a6eec36bb8aa0657fcdd39271`，73,892 bytes |

第一次实窗尝试发现内容条件在普通三元表达式中没有切换：工具栏标题已经变成“想法”，主内容仍是正文。改为 NSH 响应式 `<If>` 后复验通过；该失败没有用最终截图覆盖。第二次还发现想法视图仍显示正文页码/缩放工具，已改为在想法视图隐藏阅读工具并显示列表状态。

实窗读取到的两条想法分别来自 capture 1/2、document 1/3，均位于 `surface-vault` 第三页。最终复验重新打开的是新导入的 document 9，因此界面正确显示“先打开《runtime-three-pages.pdf》后可定位到这一页”，没有把不同 document 的引用假装成当前正文位置。

## 未覆盖

- 尚未把列表接成正式 `plugins/notes` 普通功能包；当前仍是原生实验工作区中的一个可信视图。
- 尚未实现完整想法正文分块读取、编辑历史笔记、删除、Markdown/富文本或跨退出草稿恢复。
- “打开所在页”只对当前 document 生成页码定位；本轮未通过自动化指针成功构造新选段，因此没有把当前资料的新保存/列表“打开所在页”复验写成通过。
- 没有渲染保存引用在原页上的精确高亮；没有验证缺原件、撤权、更新、卸载、崩溃与迟到结果竞争。
