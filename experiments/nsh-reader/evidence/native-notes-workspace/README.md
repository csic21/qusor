# 想法插件工作区集成记录

日期：2026-11-10。关联 F-UX-01/02、F-EXT-01/03/04/06、F-NOTE-01；设计规则见[导航层级](../../../../docs/design/navigation-hierarchy.md)与[组合规格](../../../../docs/design/composition.md)。

## 修正的问题

此前“想法”只被加到动态 PDF 阅读实验的正文工作区中，打开方式仍是独立阅读预览；它没有进入昨天完成的 `native-workbench` 统一外壳和 `PluginWorkspace` 下钻机制。因此用户无法从基座工作区入口识别“想法”是当前插件，也看不到宿主外层返回与插件内部返回的层级差异。

## 本轮集成

- `pluginWorkspaces` 新增 `fixture.notes` 工作区贡献；统一工作台侧栏和功能目录都能进入。
- 进入后退出宿主导航、对象列表和对象标签；宿主顶部持续显示 `QUSOR`、`返回产品设计`、`想法〔插件〕`。
- 想法插件拥有自己的导航、分类计数、搜索、列表和详情；宽窗为插件侧栏 + 列表/详情。
- 详情中的`返回想法列表`只回插件列表；宿主`返回产品设计`恢复进入前概览与导航。
- 再次进入同一插件会保留当前窗口内的详情选择，不伪造跨应用恢复。

## 实窗结果

| 场景 | 结果 |
|---|---|
| 从工作台侧栏进入想法 | 通过；宿主通用侧栏、内容列表和对象标签退出，插件身份持续可见 |
| 插件自有导航 | 通过；全部想法 3、当前资料 2、已收藏 1 |
| 列表→详情 | 通过；引用与个人观点分区显示，`回到原文`明确标记样例未接入 |
| 插件内部返回 | 通过；回到当前分类的想法列表 |
| 宿主外层返回 | 通过；恢复进入前的工作区概览和导航 |
| 重新进入插件 | 通过；保留当前窗口内详情选择，不复活外部资源或持久草稿 |
