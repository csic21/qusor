# M-1：独立 Wasm 插件执行实验

日期：2026-11-07。状态：本机独立执行已验证，环境、逐项结果和证据见 [实验结果](RESULTS.md)。该实验仅在本机 WSL Ubuntu 执行，不是生产插件运行时或完整安全包安装器。

## 要验证的问题

独立作者不依赖 QUSOR 源码构建的 Wasm 包，能否在不重编译宿主的情况下，通过 0.1 JSON 协议取得受控合成选区、执行简单前缀处理并返回结果；当请求越权、撤权或代码耗尽预算时，宿主能否拒绝或中止运行，并在下一次独立受监护调用中成功处理正常包。

关联 F-EXT-01/03/05/06，以及 EXT-B01、EXT-P04、EXT-P06、EXT-P11 的本机子集。完整任务定义见 [插件架构](../../docs/architecture/extensions.md)，授权及方案边界见 [ADR 0005](../../docs/architecture/adr/0005-wasm-runtime-probe.md)。

## 包与调用边界

实验读取一个目录包：

```text
package_dir/
├── module.wasm
├── manifest.json
└── package.json
```

package.json 的字段为 `format_version: 1`、`entry: "module.wasm"` 和 `sha256`。manifest.json 使用现有 0.1 策略投影；目录包是本次实验格式，不承诺作为发布包或长期兼容格式。

宿主读取约定文件、校验入口和模块摘要后再加载二进制 Wasm。摘要只证明包内声明与当前模块字节是否一致，不证明发布者、来源可信度或不可篡改分发；本轮没有签名、信任库、换钥、下载器、压缩包解包或安装回滚。

模块只允许导入 `qusor.call`，通过有长度上限的 JSON 请求调用能力。宿主注入安装身份、会话、库与授权；来宾不得在载荷中替换。禁止 start 函数及未知 imports；不提供 WASI。合成选区只在相应 SelectionRead 范围通过现有策略检查后返回，插件对实际返回的 UTF-8 字节添加前缀并输出结果；fixture 不内置选区正文。

本轮 ABI 为导入 `qusor.call(req_ptr: i32, req_len: i32, out_ptr: i32, out_cap: i32) -> i32`，模块导出 `memory` 与 `run() -> (i32, i32)`；run 的结果是最终输出的指针与长度。请求是 0.1 JSON，合成选区响应是 UTF-8 字节。这是实验 ABI，正式 SDK 绑定仍待设计。

输出只供观察本次处理结果，不保存候选、不写入正式知识、不生成操作审计或 outbox。包注册与实际能力调用都走现有策略边界；本轮没有官方插件身份特权。

## 预算与中止

以下是本轮固定的实验阈值，覆盖结果见 [实验结果](RESULTS.md)；它们不是性能承诺或全进程资源上限。修改预算时须同步更新测试、文档和结果记录。

| 限制 | 固定阈值 | 机制与须验证的结果 |
|---|---|---|
| 模块与元数据 | Wasm 256 KiB；manifest 64 KiB；package.json 4 KiB | 限制读取与解析输入，不只检查解码后的字段 |
| 总 fuel 与执行切片 | 总量 1,000,000；每片 10,000 | 切片间检查 deadline、取消与授权；总量耗尽后终止，不无限补 fuel |
| 协作 deadline | 执行 250 ms | 切片与宿主调用边界检查；不宣称可以抢占阻塞 host call |
| VM 内存与实例 | 线性内存 128 KiB（2 页）；各 1 个实例、memory、table | 超限拒绝或 trap，限制初始分配和增长 |
| 表与栈 | 表 16 项；栈最大 256 KiB；递归深度 128 | 超限失败，模块结构另外采用 EnforcedLimits::strict |
| 宿主调用 | 每次运行最多 8 次 | 反复调用不能绕过资源预算或撤权检查 |
| JSON 请求与 UTF-8 响应/最终输出 | 各最多 4,096 bytes | 同时检查大小、来宾指针/长度溢出与输出缓冲容量 |
| 取消 | 由受信任宿主控制 | 在宿主锁内检查点生效，先接受的结果不撤回；与预算耗尽、超时区分 |
| worker 看门狗 | 加载/编译/运行的监护阈值 1,000 ms | 达到阈值后尝试 kill/wait，另计 OS 调度与终止/回收耗时；下一次独立受监护调用正常包成功，终止不是业务回滚 |

取消、撤权、短同步读取与最终结果接受由宿主锁确定先后次序。取消先在锁内生效时，后续检查拒绝继续；若结果已经先被接受，随后取消不会撤回该结果。已经完成的短同步读取无法追回，也不表示已向来宾交付的内容可以收回。

fuel 不能中断正在阻塞的宿主函数，也不是宿主全部内存分配的限额。看门狗用于故障隔离；本轮没有 OS 权限沙箱、总进程 RSS/CPU 的内核级硬限制或已验证的解释器漏洞防御。运行器与包读取器属于受信任代码，不能以独立进程宣称它们获得了最小 OS 权限。

## 复现入口

从仓库根目录，在 WSL Linux 路径运行 [完整验证脚本](validate.py)：

```sh
python3 experiments/extension-wasm/validate.py --output /tmp/qusor-wasm-results.json
```

脚本构建作者工具与运行器，先打包全部 fixtures，再执行格式检查、测试和 Clippy；同时验证 CLI 正常/失败路径、父进程看门狗与下一次独立调用、两版包输出和宿主二进制 hash 不变。不能仅打包两个正常示例后直接运行全套测试，反例也依赖各自目录包。脚本将复现证据写入指定 JSON 文件，当前已记录的环境与结论见 [实验结果](RESULTS.md)。

作者与运行器各有独立 Workspace/lockfile。首次准备锁定依赖缓存时，分别对实验 Workspace 与 author Workspace 执行 `cargo fetch --locked`；验证脚本的构建与运行采用离线检查，实验不访问网络。手动作者调用方式和包格式见 [独立作者说明](author/README.md)。完成完整脚本后，可单独重跑正常包：

```sh
cargo run --manifest-path experiments/extension-wasm/Cargo.toml -p qusor-wasm-probe --locked --offline -- experiments/extension-wasm/packages/valid
```

每次 CLI 调用均新建监督父进程和 worker，未验证同一长驻宿主内重新加载；`--worker` 是内部受控子进程模式，`--block-host-call` 仅用于受信任测试的宿主阻塞故障注入，均不是插件可请求的权限。输出与包/模块/宿主 hash 集中记录于 [实验结果](RESULTS.md)，不在本文重复维护。

## 验收范围与证据

逐项结果、失败码与环境见 [实验结果](RESULTS.md)；下表保留验收范围，不将本机结果推广到全部平台或未覆盖攻击路径。

| 场景 | 预期 |
|---|---|
| 独立作者构建两版包 | 无 QUSOR path 依赖，两个模块 hash/处理结果不同 |
| 同一宿主加载两版包 | 运行器二进制 hash 不变，输出符合各自版本 |
| 正常选区请求 | 仅返回授权的合成选区，输出前缀处理结果 |
| 跨库与未授权能力 | 明确拒绝，不返回未授权内容 |
| 撤权与旧会话 | 下一次能力调用或执行检查拒绝；旧许可不恢复 |
| 死循环与 fuel | 总预算耗尽可结束，下一次独立受监护调用正常包成功 |
| 内存/表/栈超限 | 拒绝或 trap，未被当作成功 |
| 请求/响应/输出越界 | 拒绝超限与非法内存区间，不发生越界访问 |
| start/未知 import/坏包 | 在执行处理逻辑前拒绝，摘要不匹配也拒绝 |
| deadline/取消 | 在相应检查点得到独立失败码；取消不撤回已先接受的结果 |
| 宿主阻塞与看门狗 | 本机样本中 worker 被终止并回收，下一次独立受监护调用正常包成功 |

工具链、锁文件、构建模式、OS/设备、包/模块/宿主 hash、执行命令、退出状态和输出统一维护于 [实验结果](RESULTS.md) 与验证脚本产出的 JSON。未测试的攻击路径明确保留，不根据通过的正常示例推断。

## 失败后的备选与未验证项

若 fuel 恢复、取消或预算边界无法可靠强制执行，停止该 profile 的生产推进，保留最小复现；先修复预算/调用边界，再比较其他受限解释器或执行器实验。若阻塞 worker 无法可靠回收，停止以该包装方式承诺可恢复运行，补充操作系统级进程管理验证。替代路线仍须独立包、权限和平台证据，不能退回内置特权演示充当通过。

即使本机用例通过，EXT-B01 的平台/渠道矩阵与 EXT-P04 的真实事务/网络路径、EXT-P06 的全部宿主资源、EXT-P11 的完整发行 SDK 仍未完成。未注入 kill/wait 失败，1,000 ms 是触发阈值，不承诺任意 OS 故障下按时回收。本轮不覆盖长驻多插件宿主恢复、真实知识保存/导出、持久任务恢复、发布者信任/签名、完整安装升级回滚、真实官方功能包、网络/凭据 broker、NSH UI、原生平台或移动分发。
