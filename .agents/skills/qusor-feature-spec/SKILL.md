# QUSOR 功能规格

先读 [功能范围与确认记录](../../../docs/product/scope.md)、[体验设计](../../../docs/product/experience.md) 和当前用户要求。

## 确认范围

区分长期已明确要求、当前交付、推荐排期与待确认选择。不要重问原愿景已经明确的长期需求；不要把未回复、默认选项或技术报告的推荐记为用户同意。

只检查当前任务仍缺失且会改变产品行为或阶段规模的选择：首版AI/画布/同步、数据出站、首发平台和编辑深度；不重问已有答案或当前无关的项目。一次聚焦少量问题，等待答案时继续不依赖答案的工作。具体库和普通工程细节由技术负责人验证决定。

使用现有Feature ID；新需求确有独立行为时新增ID。记录用户决定日期、适用阶段及关联功能，不把一次例外变成永久全局规则。

## 写规格

用 [功能模板](../../../docs/templates/feature-spec.md) 描述目标、入口、主要流程、取消/失败/离线状态、数据归属与来源、可观察验收、依赖。

涉及AI写入时区分保存候选内容与提交正式知识，支持批量审核，不强制逐项弹窗。文档或目标实体版本变化后重新校验，影响结论或写入目标时才需要重新审核；保留撤销与记录。涉及云时分开说明同步、模型调用和原文件上传；凭据不进入普通业务数据。

第一阶段第三方支持和第一方功能插件化已确认，不再询问是否延后。阅读及其他核心用户工作流的 [插件归属](../../../docs/architecture/workspace-layout.md) 已明确；C-08 的前置实验与本地闭环顺序已获授权，首版附加功能、云默认行为和首发平台仍分别处理。每项功能规格标出插件归属、贡献点、宿主能力、停用行为与SDK验收；共享数据/权限不变量保留Core。具体插件排期仍按功能范围记录。

涉及插件时区分通用扩展需求、具体来源插件排期、第三方开放范围和平台执行能力。示例不自动变为首版需求；只问当前缺失的产品选择，不要求用户选择Wasm/JS等运行时。外部选文验收同时描述本地保存与实际外部回跳能力。

保持阅读安静。产品界面只呈现用户做决定需要的信息，不堆叠RPC、数据库或crate术语。

## 例子

用户说“笔记中保存AI解释”：保留已经确定的审核/撤销要求；确认仍缺失的首版范围或出站偏好，说明选区→回答→来源核对→候选→接受/拒绝的验收，不擅自扩展为后台扫描整库。

用户说“先只做基座”：补齐规格、技能和工程边界，不生成阅读器或假AI页面。已有授权范围内的配置文件无需逐项再问。

## 完成条件

范围记录与规格一致，待确认事项明确保留，验收可由用户观察。用户后续明确指令可以更新交付范围；已授权工作不增加重复审批。实现仍须满足相应技术门槛；技能本身不授权部署、上传或访问新资料范围。
