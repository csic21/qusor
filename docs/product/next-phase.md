# 下一阶段：插件化收敛与本地阅读闭环

> 权威范围：本文件维护**阶段实施顺序、准入/退出门槛与架构收敛路线**（[ADR 0048](../architecture/adr/0048-doc-governance.md)）。各 Feature 与模块的实时实现/验证状态统一见 [项目状态表](../status.md)；产品范围与待拍板项见 [功能范围](scope.md)。

## 总体目标与用户验收

- **核心阅读闭环**（关联 `F-LIB-01`、`F-READ-01/02/03`、`F-NOTE-01`、`F-SRC-01`、`F-DATA-01`、`F-EXT-01/03/04/05/06`）：导入资料 → 阅读选文 → 保存摘录与个人笔记 → 关闭重开 → 从笔记准确回原文 → 完整导出并恢复。普通文本 PDF 先行，随后扩展 EPUB。
- **通用基座方向**（关联 `C-11/12/13/18`、`F-UX-01/02`、`F-AGENT-01–05`）：维持通用插件/Agent 外壳，不把具体场景（阅读或开发文件树）写死为全局强制布局；界面与对应功能同步交付。
- **核心不变量**：`“保存成功”` 仅以 Core 持久提交回执为准；引用与个人观点分开；停用/卸载插件后已收录规范内容仍可通用查看与导出恢复。

## 收敛路线（2026-11-14 架构评审后）

按顺序推进以下五阶段；涉及待用户拍板事项（见 [范围记录](scope.md#待用户拍板的关键架构选择)）的阶段在确认前仅完成设计与隔离实验：

| 阶段 | 核心任务 | 退出门槛 |
|---|---|---|
| 1. 止血与治理 | Host API 改为累积兼容并冻结新增业务专属枚举；清理 `apps/qusor` 写死 vault/包 ID 与旁路直调并机械拆模块；确立文档治理与 `docs/status.md` | `check_docs.py` 与 `check_app_boundary.py` 通过；累积兼容单测通过；跨文档版本/依赖图漂移消除 |
| 2. 端口与分层重构 | 拆分 Query（有界分页/按 ID）/ Command（增量事务）/ Archive（全量导出恢复）端口；消除常规读写加载原件 blob；第二阶段处理 Core 命名与 `extension-ports` | 万条摘录 + 大 PDF 下按 ID/分页读不触发原件 blob 读取；事务/审计/outbox 原子语义保持 |
| 3. 插件协议与运行时 | 正交命名空间能力 + 每能力 semver 协商；WIT/Component Model ABI、`qusor-sdk` 与 `qusor dev`；插件 UI 协议（待用户拍板后定型）与预算可配置化 | 仓库外用 SDK 构建真实插件（带 UI + 读写 Core）通过宿主验证 |
| 4. 官方功能迁出 | 按“词汇 → 笔记 → 资料库 → 阅读”顺序将 `apps/qusor` 业务逻辑迁入 `plugins/*`；PDF/EPUB 引擎下沉为 Host 原生服务 | 停用插件后宿主无残留业务 UI，已存知识仍可导出与查看 |
| 5. 六端与发行门槛 | 待拍板 iOS/Web 动态插件策略后，补齐 Windows 存储/PDFium、iOS/Web 执行与各端签名/公证/自动更新流水线 | 各声明平台分别完成构建、运行与恢复留证 |

## 插件与宿主契约约束

- 工作区、阅读与笔记由独立插件贡献，Host 不按官方包 ID 写业务分支。
- Core 持有文档版本、摘录、笔记与引用；Host 持有身份、授权、包生命周期、平台资源与恢复。
- PDF/EPUB 服务仅提供受控数据与 opaque handle，不向插件暴露 NSH 节点、数据库连接或任意路径。
- 官方包与仓库外第三方示例使用同一公开协议与权限边界；历史详细实验证据索引见 [项目状态表](../status.md) 与各 `experiments/*/RESULTS.md`。
