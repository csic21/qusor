# 插件安装、更新与恢复规格

日期：2026-11-07。状态：用户已授权推进下一阶段；本文为待实现、待验收的工程规格，不表示包管理器或产品 UI 已完成。关联 F-EXT-01/03/04/05/06，技术细节见 [生命周期架构](../architecture/plugin-lifecycle.md)，范围以 [范围记录](scope.md) 为准。

## 1 目标和范围

用户可以主动取得官方或第三方插件包，在不修改主程序、不重新编译应用的情况下安装和使用；重启后保留有效安装与明确授权，更新失败可恢复，停用或卸载不丢已保存知识。第一方阅读、资料库、笔记及后续能力采用同一包类型和管理入口。

本阶段先实现可复现的离线安装与持久恢复实验，再按技术门槛接入正式宿主和阅读闭环。包管理入口是 Host 自带管理能力，不能依赖被修复的插件加载成功。下一步不要求建设市场、账户、付费、后台自动更新、任意插件依赖安装或云同步。

已确认的是第三方开放、第一方同权和推进下一阶段的方向；首发平台、Reader AI/画布/同步交付深度、云端默认行为仍以原范围记录为准。后续最小实验限定合成输入，不连接用户账号、不上传用户资料。

## 2 用户流程

### 安装和启用

1. 用户从插件管理入口选择已取得的包。
2. 宿主验证完整内容、发布者信任、版本及本机可用能力。篡改、身份冲突、不兼容或未知必需权限时给出原因，不执行该包。
3. 首次来源信任由宿主展示发布者标识/密钥指纹和来源，签名不自动代表已认证现实身份。安装确认与能力授权分开呈现，可以合并在一个清晰流程中，不能把安装等同于授予全部权限。
4. 只有包内容和安装记录均可靠保存后才显示“已安装”。未授权或缺必需能力时显示“已安装，未启用”。
5. 用户授予明确资料范围和能力并启用；激活完成后显示插件贡献入口。授权被拒绝不影响其他插件或宿主管理入口。

离线包可以离线完成本地校验和安装；依赖远程证明但本地没有充分证据时保持未启用，不声称已完成联网验证。失败时保留当前有效安装，暂存内容可安全清理。

### 重启和恢复

重启后恢复安装记录和仍有效的持续授权，再创建新的执行会话。一次性选区、文件句柄、旧回调和待消费运行许可全部失效；相关动作要求重新获得上下文。损坏包、失效来源信任、不兼容版本或未完成更新显示“需要修复”，并可查看原因、安装修复包、禁用或卸载。

用户已提交的确定性操作先查询保存回执。已提交但未显示结果的操作不能重复产生内容；待审核的 AI 或其他正式写入候选可以保留，但不能凭重启前的过期批准自动执行。

### 更新与回滚

用户选择新包后，先看到版本、来源身份和权限差异。新包校验失败时当前版本继续保持；进入切换后停止旧实例，迁移私有设置的副本并检查新包可加载。成功更新后保持禁用、清空旧授权，用户重新授予权限并启用；新增权限绝不隐式继承。

若在停止旧实例后更新失败，恢复匹配的旧包和旧私有设置并显示失败原因，保持禁用，重新启用时创建新会话。显式回滚也重新验证历史包并要求重新授权，不能复活旧会话。回滚不撤销新版本已经保存的笔记、摘录或其他正式知识；这些内容的修改使用单独的编辑/撤销流程。

取消发生在持久切换之前则保持原包引用；若旧实例已停止，保持禁用以便重新启用。持久切换完成后“取消”不能隐式倒退版本，应明确提示已完成并提供回滚入口。

### 禁用和卸载

禁用立即停止接受新调用、撤销旧上下文并移除贡献入口；运行资源回收状态独立展示。故障进程无法确认终止时显示需修复，并阻止同一安装启动另一个实例。

卸载移除可执行入口和安装授权，可明确选择是否保留私有设置；已收录正文、来源、笔记、引用和完整导出能力继续可用。删除知识始终是另一项用户操作。卸载中断后继续清理，不自动恢复运行；重新安装是新的安装实例。

## 3 插件与宿主边界

| 项目 | 约束 |
|---|---|
| 功能归属 | 本规格描述 Host 包管理；被管理的官方功能插件与外部包地位一致 |
| SDK | 现有 0.1 为未发行策略协议；实际发行 SDK 必须含权威 schema/绑定、manifest、错误/权限/版本规范、打包和验证方法 |
| 贡献点 | 通过已登记 Command/SelectionAction 及后续公开视图/Surface 契约发现，不硬编码官方包业务入口 |
| 最小权限 | 安装/迁移预检不获得真实知识、网络或 UI 业务能力；正式启用按包摘要和具体资源授权 |
| 数据所有者 | Host 保存包/安装/授权/故障状态；Core 保存正式知识及事务记录；插件只持有受控私有设置和缓存 |
| 停用后 | 高级插件交互可停止；宿主仍可管理/修复插件、通用查看已保存内容及完整导出恢复 |
| 独立验证 | 作者仅拿发行 SDK 工件在仓库外构建；宿主二进制摘要不变；官方包接受同样的拒绝/撤权/更新规则 |

包版本、SDK、私有设置和 Core 数据版本分开。SDK 缺少官方阅读或其他功能所需能力时，先补公开契约和验证，不增加官方私有直连。发布 SDK 不等同于已承诺全部贡献点或跨平台执行。

## 4 可执行验收

以下全部为待执行场景；沿用已有 EXT 编号，一个编号可以有多个细化场景。脚本必须记录输入包/宿主摘要、执行环境、动作、故障注入位置和可观察结果。

| 关联门槛 | 场景与动作 | 通过条件 |
|---|---|---|
| EXT-B02，EXT-P11 | 仅将 SDK 发行工件和文档交给仓库外作者，构建两个版本 | 构建依赖无 QUSOR 源码路径；同一宿主字节执行两个独立包 |
| EXT-B04，EXT-P13 | 分别篡改运行入口、manifest 权限、资产与清单 | 全部在执行前拒绝；不能仅因模块摘要一致而接受被改 manifest |
| EXT-B04，EXT-P13 | 同名/同包 ID 换陌生签名键、回放旧换钥证明 | 拒绝接管；有效换钥按独立信任流程接受，身份可追溯 |
| EXT-B04，EXT-P06 | 路径穿越、链接、重复路径、解包超量，以及校验后并发替换输入 | 拒绝或使用已冻结的已验证内容；不得执行替换字节 |
| EXT-B04，EXT-P13 | 在暂存、内容落盘、安装记录提交前后逐点终止进程 | 重启能判定未安装或完整已安装；不会执行半包，不丢旧有效引用 |
| EXT-B03/B04，EXT-P04 | 重启后重放旧 session、文件句柄、授权许可和回调 | 全部拒绝；仅对相符的持久授权创建新会话，过期选区不复活 |
| EXT-B03，EXT-P04 | 撤权与实际 Core 提交交错，包含提交后响应丢失 | 提交/撤权有明确顺序；先撤权者无写入，先提交者有唯一回执；本场景需真实 Core 事务才可通过 |
| EXT-B04，EXT-P08 | 更新增加权限、不兼容 API、未知必需能力 | 不自动执行不兼容包；成功更新禁用且旧授权为空；新增权限需重新授权 |
| EXT-B04，EXT-P08/P13 | 私有状态迁移抛错/超时，在版本切换前后终止进程 | 包与私有状态成对恢复；旧会话不可用；新代码不读取不匹配旧状态 |
| EXT-B04，EXT-P08 | 更新后提交知识，再回滚至保留旧包 | 私有状态与旧包匹配，世代只前进；已提交知识及操作记录不回滚；需真实 Core 验证 |
| EXT-B03，EXT-P06 | 同一长驻 supervisor 中 A 正常、B 死循环/崩溃/host call 阻塞 | B 有界失败，A 继续可调用，管理入口可用；B 重试用新会话 |
| EXT-B03，EXT-P06 | 注入 kill/wait 失败、旧 worker 延迟返回、连续启动失败 | 隔离故障安装、不并发启动替代者、不接受旧结果；重试有界 |
| EXT-B03/B04，EXT-P04/P13 | 禁用/卸载持久提交后终止进程，再尝试旧回调和重装 | 禁用/卸载状态保留，清理可继续，重装获得新安装 ID |
| EXT-B06，EXT-P03/P13 | 真实收录、用户笔记和引用形成后卸载包，导出并向空库恢复 | 内容、出处、引用保持，凭据不在导出；不能以合成字符串或内存对象代替 |
| EXT-B07，EXT-P12 | 官方功能包以普通身份运行、撤权、替换/停用 | 功能真实使用同一 SDK；无固定官方身份特权，无隐藏宿主业务回退 |

一次本机实验通过只覆盖其实际环境。发布还需所选 profile 的 EXT-P07 与承诺平台结果；这里不替用户选择首发平台。未实现真实 Core/NSH 的场景保持未执行，不用策略回调或命令行输出代替业务验收。

## 5 最小阶段与退出条件

| 顺序 | 下一份可审查交付 | 结束条件 |
|---|---|---|
| 1 | 独立包格式与 SDK 工件实验，完整性/本地发布者信任用例 | 外部构建成功；坏包、身份接管和路径攻击拒绝；明确仍未覆盖的发行/平台事项 |
| 2 | 持久安装、授权恢复、更新/回滚/卸载实验 | 每个关键落盘/切换点有崩溃注入证据；重启不复活旧上下文 |
| 3 | 长驻双插件监督与故障恢复实验 | 同一 supervisor 处理正常/故障插件，取消与回收失败有可观察结果 |
| 4 | 依据平台证据将最小适配器接入正式宿主，连通首个真实保存用例 | 真实 Core 事务、知识保留/导出及官方同权分别验收，不能只累计实验测试数量 |

前三步可以复用 [既有 Wasm 候选](../../experiments/extension-wasm/README.md)，不自动决定生产运行时。NSH 阅读承载验证可与它们并行；正式官方阅读插件的发布依赖公开 Reader/Surface 契约和真实存储/定位门槛。暂不实现中心市场、插件任意互依、自动云分发或所有未来贡献点。

任何阶段遇到故障隔离、持久恢复或渠道阻断，记录失败输入和替代方案，保留用户已确定的第三方与第一方同权目标。技术验证可以调整实现，不将未通过的功能标为完成。
