# QUSOR 功能基线与范围确认

更新：2026-11-07。状态：第一阶段第三方插件及第一方功能插件化已确认；首版其他功能范围和云端偏好待用户确认。推荐不等于确认，未回复不表示同意。

## 当前工作范围

前期已确认先做技术架构基座、引入技能和设计文档，功能先不实现。当前已按最小可检查骨架建立工程与协作基础，不接 NSH/数据库/模型或云服务。

本轮不实现阅读器、知识库、画布、Agent、学习或同步；不把它们的设计文档当成功能完成。

2026-11-07，用户在架构拟定后明确提出开始 UI / UX / UE 设计准备，当前先研究优秀设计。本轮新增公开案例调研与体验方向探索，成果见 [设计参考研究](../research/07-ui-ux-design-study.md)；尚未冻结视觉方案，也未授权业务 UI 实现，首版功能和云端选择仍保持待确认。

## 插件化确认记录

2026-11-07，用户明确要求基座支持插件化，RSS与微信读书集成只是扩展能力的例子。已确认F-EXT-01至F-EXT-04；能力目录、来源快照和生命周期设计见 [插件架构](../architecture/extensions.md)。不重新询问是否需要插件化。

这次确认不意味着首版必须交付RSS或微信读书插件，不意味着已有公开选区API，也不意味着移动端允许下载执行任意插件。具体服务先验证可用入口。随后用户明确“第一阶段就支持，我们的功能开发也围绕插件化进行”，因此C-07已确认，新增F-EXT-05/F-EXT-06，第一阶段按M0规划；架构详见 [ADR 0003](../architecture/adr/0003-plugin-first-delivery.md)。原有C-02/C-03未被此次消息回答。

## 首版推荐闭环

建议以“导入 PDF/EPUB → 阅读 → 高亮/批注 → 笔记 → 重开回源 → 导出恢复”为基础。中文搜索、异常资料处理、基础无障碍属于交付质量，不单独推迟为装饰。

Reader AI 按原愿景建议保留 M0，但当前问题允许用户选择延后。如果上线 AI 回答，F-AI-02 必须同时具备；如果允许 AI 保存内容，F-AI-03 同时具备。

画布/知识图谱建议 M1。富文本建议在 Markdown 基线可靠后扩大；无 DRM 的常见 PDF 与可重排 EPUB 为候选首版支持范围，不预先承诺所有电子书排版。

以上是推荐方案，尚未标记用户接受。

## 随后细化

后续按实施阶段与影响范围确认以下内容，不一次追加大量问题：

- C-04 首发平台：主用桌面端与首版必须验收的平台；长期五端目标保持。
- C-05 笔记编辑：Markdown足够，还是首版需要所见即所得；两者的存储权威性明确。
- C-06 资料支持：网页是保存链接还是离线抓取；扫描PDF需不需要首版OCR；复杂EPUB排版深度。

PDF/EPUB库、数据库库和布局算法由技术验证决定，不要求用户替工程团队选择具体库。

## 当前非目标与约束

第一版不做多人实时协作；不因同步提前引入复杂CRDT。移动端不强求复杂画布与桌面完全一致。不以图形效果牺牲阅读/性能，也不以AI自由写库绕过审核。

本轮不创建生产迁移、模型请求、云资源或UI功能。M-1和业务开发是后续阶段，工程可编译不表示其验收通过。
