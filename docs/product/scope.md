# QUSOR 功能基线与范围确认

> 权威范围：本文件维护**已明确的产品要求（Feature ID）、用户确认决策（C 编号）、待用户拍板事项与非目标边界**（[ADR 0048](../architecture/adr/0048-doc-governance.md)）。各功能与模块的实现/验证进度统一见 [项目状态表](../status.md)，实施顺序见 [下一阶段计划](next-phase.md)。

## 已明确的产品要求

来自原始愿景及用户后续明确指令的长期要求，无需重新询问“是否需要”；需要确认的是首版深度、上线顺序和默认行为。

| Feature ID | 要求 | 建议排期 | 用户可观察的验收 |
|---|---|---|---|
| F-LIB-01 | 本地 PDF/EPUB 资料库，保留原文件 | M0 | 导入、查找、关闭重开后仍可读，原件没有被改写 |
| F-LIB-02 | Markdown、网页文章、报告及附件管理 | 分阶段，首版深度待细化 | 资料格式与来源可辨，缺失/不支持状态明确 |
| F-LIB-03 | 标签、分类、全文搜索 | M0 | 中文关键词可找到资料和原文片段 |
| F-READ-01 | PDF 阅读、目录、缩放、进度、书签 | M0 | 连续阅读并恢复到原位置 |
| F-READ-02 | EPUB 目录、重排、字号/行距/宽度/主题 | M0 | 换字号/窗口后仍能找到同一段 |
| F-READ-03 | 划线、高亮、批注 | M0 | 可保存、编辑、删除，重开位置正确 |

| F-LEARN-02 | 测验、理解反馈、对比和因果链练习 | M2 | 可以检查理解并纠正 AI 判断 |
| F-LEARN-03 | 学习路径与掌握情况 | M2 | 学习顺序和进展可见、可调整 |

| F-AGENT-03 | 跨 Agent 委派与指定后端模型 | 本轮设计，验证后实施 | 父子任务可追踪，实际模型可核对 |
| F-AGENT-04 | 本机编程与电脑操作 | 本轮设计，平台及授权待定 | 项目文件/命令与屏幕/输入按范围执行 |
| F-AGENT-05 | 多任务监督、恢复与成果管理 | 本轮设计，验证后实施 | 停止和重启不伪报完成或重复副作用 |
| F-SYNC-01 | 账户、设备、增量同步和冲突处理 | 架构预留，上线阶段待定 | 双设备离线编辑后不静默丢内容 |
| F-SYNC-02 | 可选云备份与文件同步 | 同步上线时 | 用户决定上传范围，原书不默认上传 |
| F-PLAT-02 | 桌面/移动发行与自动更新（GitHub Release + 签名清单） | 随 C-17 推进 | 已装版本能校验并安装更新；移动端给出商店链接或 OTA 包；首次发布即内置更新配置 |
| F-PLAT-01 | Windows/macOS/Linux/Android/iOS/Web | M-1 验证，首发门槛待定 | 已声明支持的平台有真实安装与使用记录 |
| F-EXT-01 | 通用插件扩展接口，新增来源/处理/工具能力不绑定 Core 内部实现 | M-1 验证；M0 功能开发前建立 SDK 与宿主 | 两个不同来源经同一契约接入，不增加服务名领域分支 |
| F-EXT-02 | 外部阅读选段进入知识库，保留出处与本地快照 | 契约现在；具体服务排期待定 | 保存选文可检索、引用；本地回源与外部回跳等级明确 |
| F-EXT-03 | 插件启停、升级、权限与数据生命周期 | M0 插件基础前置 | 撤权有效；卸载不丢已收录知识；升级不自动扩大权限 |
| F-EXT-04 | 插件贡献命令、选区动作与视图，桌面/移动共享数据契约 | 分阶段开放扩展点 | 入口不破坏安静阅读；无插件也可阅读/导出核心内容 |
| F-EXT-05 | 第一阶段支持第三方开发、独立打包、安装、分发和更新 | M0 必需；M-1 先验证 | 作者仅用公开 SDK 制作包，用户安装不修改主程序、不重编译 |
| F-EXT-06 | 第一方功能也以插件开发，消费相同公开 SDK 与贡献点 | 所有后续功能开发 | 正式官方功能可按普通插件身份运行、更新和停用；没有私有写库/UI 后门 |
| F-UX-01 | 安静阅读、场景化呼出 AI | M0 起 | 正文优先，AI 不持续遮挡或打扰 |
| F-UX-02 | 键盘、触控、基础无障碍 | M0 起 | 不依赖鼠标或网络图视觉也可完成关键任务 |

## 插件化与来源确认

- 2026-11-07 确认插件化为基座要求（F-EXT-01 至 F-EXT-06），第一阶段开放第三方开发/安装/分发，第一方功能围绕同一公开插件契约开发（[ADR 0003](../architecture/adr/0003-plugin-first-delivery.md)）；RSS 与微信读书仅作来源验证例（微信读书接入研究见 [源码研究与接入验收](../research/08-weread-plugin-study.md)，不自动确认账号接入排期或默认抓取）。
- 仓库托管于 [csic21/qusor](https://github.com/csic21/qusor)，采用 [MIT 许可证](../../LICENSE)；crate 继续保持 `publish = false`。

## 首版推荐闭环

建议以“导入 PDF/EPUB → 阅读 → 高亮/批注 → 笔记 → 重开回源 → 导出恢复”为基础。中文搜索、异常资料处理、基础无障碍属于交付质量，不单独推迟为装饰。

Reader AI 按原愿景建议保留 M0，但允许用户选择延后（上线 AI 回答须同时具备 F-AI-02，允许 AI 保存须同时具备 F-AI-03）。画布/知识图谱建议 M1；富文本建议在 Markdown 基线可靠后扩大；无 DRM 常见 PDF 与可重排 EPUB 为候选首版范围。本节建议不视为已确认。

### 待用户拍板的关键架构选择（2026-11-14 架构评审提出）

1. **第一方功能的交付形态**：保持 [ADR 0003](../architecture/adr/0003-plugin-first-delivery.md)“第一方亦独立动态包”，还是放宽为“同一公开契约、两种交付形态（第一方静态链接仅调用公开 SDK trait + 第三方 Wasm 包）”？
2. **iOS / Web 第三方插件策略**：是否必须在 iOS / Web 支持动态安装执行第三方插件，还是接受“商店版/Web 仅随包插件 + 纯声明式插件”？
3. **插件 UI 技术路线**：采用自定义声明式原生 UI 树协议（Wasm 产出节点/patch + Host 渲染），还是采用 NSH TSX/JS 受限隔离运行时？

> 未收到用户明确答复前，相关 ADR 必须保持 `Proposed`，不得自动落地依赖未决选择的生产实现。

## 随后细化与非目标边界

- **随后细化**：C-04（各端最低系统版本与渠道资格）、C-05（Markdown vs 所见即所得编辑权威性）、C-06（网页离线抓取、扫描 PDF 首版 OCR、复杂 EPUB 深度）。PDF/EPUB/数据库/布局库由技术验证决定。
- **当前非目标**：第一版不做多人实时协作或复杂 CRDT；移动端不强求复杂画布与桌面完全一致；不以图形效果牺牲阅读性能，也不以 AI 自由写库绕过审核。
- **决定落地方式**：收到用户答案后更新 C 编号、选择、日期、关联 Feature ID 及影响阶段；首版功能使用 [功能规格模板](../templates/feature-spec.md) 补齐规格与验收。
