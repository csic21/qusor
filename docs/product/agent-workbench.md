## 用户目标与范围

用户希望 QUSOR 能操作自己的电脑进行编程，接入多种现成 coding agent，统一调度 Codex、dsh、OpenCode 中的指定模型并管理会话，参考 Herdr；同时要求整体架构和 UI/UX/UE 认真设计。这里按编程理解上一条消息中的“变成”。电脑操作长期涵盖命令、文件、应用与图形界面；具体执行平台、首版深度和默认授权尚未冻结。

| Feature ID | 已明确需求 | 用户可观察结果 |
|---|---|---|
| F-AGENT-01 | 通用多 Agent 接入，编程后端为其中一类 | 能发现、配置和选择实际可用后端，区分角色配置、模型直连与完整 Agent；能力差异明确 |
| F-AGENT-02 | 统一管理会话 | 查看、继续、接管、停止会话，保留各后端原生会话身份 |
| F-AGENT-03 | 跨 Agent 委派和指定模型 | Codex 可提交给 dsh 的子任务，也可指定 OpenCode 的 provider/model；能检查执行方、输入范围和结果 |
| F-AGENT-04 | 操作本机编程环境与电脑 | 在授权项目中编辑、运行命令和检查成果；电脑图形操作按能力独立启用 |
| F-AGENT-05 | 多任务监督、恢复与成果管理 | 不盯终端也能知道哪里需要介入；中断后能判断是否仍在运行以及已发生哪些修改 |

本轮交付范围是设计及验证计划。阅读闭环既有成果与门槛继续保留；新增需求不自动确定全部进入首版，也不默认安装后端、读取外部会话、改第三方配置或连接账号。

2026-11-09，用户进一步明确“以后写代码什么我都希望在这上面弄”。C-13/F-AGENT-04 因此细化为长期日常开发工作区目标：项目/文件/搜索、手动编辑与 Agent 协作、真实终端/检查、Git/工作树、运行预览及后续调试在统一外壳中连贯完成。设计见 [开发工作区](../design/development-workspace.md)。本轮补设计与验收，不启动外部后端，不把全部 IDE 深度、跨设备执行或部署列为已完成/已冻结首版。

## 主要流程

1. 打开“任务”工作区，选择项目和执行设备。明确显示当前机器、目录、分支及已有未提交修改；接入工具时由用户选择可执行程序/服务和账号配置。
2. 输入目标，选择负责人或使用已配置的调度策略。展开后可选执行器、模型、允许的目录/网络/电脑能力及预算；常用策略可复用，扩大范围才重新请求。
3. 创建持久任务后再启动执行。界面持续显示当前执行方、最近动作、阻塞原因、实际文件变更与子任务；正文保留用户目标，长日志按需展开。
4. Agent 通过统一委派入口请求另一个后端。用户可以查看和修改委派策略、深度与预算；子任务拿到明确任务包及所需资料，不自动接收全部聊天、凭据或整个知识库。
5. 需要用户时进入“待你处理”，就地展示问题/权限/差异并链接对应任务。接管时先取得会话输入权，避免用户和调度器同时发指令。
6. 完成后展示变更、实际检查结果和待办。修改了文件、测试通过、提交到 Git、合并、部署分别记录。把成果保存为知识时仍走 Core 的引用、审核和事务。

“继续已有会话”优先绑定同一后端的原生 ID。切换到另一个后端创建新会话并提供交接摘要、资料和变更清单；界面称“交接”，不声称原生上下文无损迁移。不支持的恢复/分叉/模型切换应明确禁用及说明。

## 失败、取消、离线

| 情形 | 行为 |
|---|---|
| 模型断网/额度不足 | 保留输入、任务及已发生的修改；可重试或交接给另一后端，不能假定重试没有副作用 |
| 停止父任务 | 立即禁止新委派并请求停止子任务/命令；分别显示停止请求与确认，不假称已回滚文件 |
| 关闭面板/窗口 | 不等于停止任务；退出应用前说明执行服务是否继续，未验证常驻时不得承诺后台持续运行 |
| 重启后状态未知 | 先核对进程与原生会话；结果未知时禁止自动重复写入/提交/部署，提供检查入口 |
| 多个任务改同一项目 | 并行写入优先独立 worktree；非 Git 项目按写入租约串行；不能靠 UI 提示代替隔离 |
| 严格离线 | 本地文件、历史及已接入本地后端可用；云后端明确不可用，不能静默切云或上传 |
| 图形操作中用户移动鼠标/切窗 | 暂停自动输入并重新核对目标；控制状态可见，停止入口始终可达 |

## 插件与公开能力

规划 `plugins/agent-workbench/` 提供任务工作流；`plugins/agent-backends/<backend>/` 通过公开版本化契约贡献后端；`plugins/agent-orchestrator/` 提供可替换调度策略。目录尚未创建，名称不是已发布 package ID。会话视图、差异检查和终端视图按 [组件组合](../design/composition.md) 提供可替换角色。普通插件不得拿到 Host 私有对象或知识数据库。

Host 提供通用任务记录、委派 broker、授权、进程/终端/电脑服务及恢复；后端通过受控连接接入。工具调用和原生消息由适配器翻译，不要求所有 Agent 使用 Pi 的会话模型。第一方与仓库外第三方须用相同 SDK、贡献点和授权；安装仅声明能力，运行时逐次判权。当前 API 0.2 不具备这些通用契约，不把设计名当成已可调用方法。

## 数据、权限与导出

任务/事件/委派关系/后端绑定属于宿主操作记录；正式笔记与来源仍归 Core；项目源码保留在用户项目中，原生会话由对应后端管理。QUSOR 保存能通用查看/导出的任务记录与成果索引，不承诺所有第三方内部会话可完整备份恢复。卸载后端后历史仍可读，继续执行显示缺少提供者。凭据不进入普通导出，截图和终端日志按敏感内容处理，可配置保留期限与日志保存范围。

本地执行可以按用户预先授权的项目策略连续改文件、运行测试，无需逐个命令弹窗；知识库正式修改继续满足 F-AI-03 的单项或批量审核。允许直接执行代码的后端可能拥有文件/网络权限，必须声明实际约束能力；Host 的消息审计不能证明任意子进程已被 OS 限制。

| AW-17 | 手机/窄窗在文件、代码、任务和输出间单页切换；执行设备始终可辨，没有连接时不显示远程可用或承诺本地桌面 CLI |

## 建议验证顺序

先做两个真实后端、单项目、结构化会话与恢复；再做跨后端委派、独立工作树和成果检查；终端交互与电脑图形操作各自过门槛。随后结合阅读引用，验证“从资料提出实现任务，再把成果收录回知识库”。这只是建议顺序，不能替代首版范围与平台决定。
