# 无界面插件宿主策略基座

日期：2026-11-07。状态：本轮策略内核、示例和本地检查已完成。本文描述可直接调用和测试的宿主策略内核，不代表完整插件 SDK 或独立包安装能力已交付。

## 功能与范围

关联 F-EXT-01、F-EXT-03、F-EXT-04、F-EXT-06。用户在前期调研后明确“先把我们的基座功能实现一下”，因此 [C-01](scope.md#当前选择记录) 从文档与工程骨架推进到无界面基座实现。UI 研究继续并行，首版 AI、画布、同步与云端默认行为仍未确定。

本轮选择可独立验证、可供后续运行适配器复用的完整切片：版本化协议 → 安装元数据注册 → 能力协商与显式授权 → 绑定宿主会话的调用检查 → 撤权、启停、升级与卸载。它解决“宿主是否允许此安装实例在此库访问此资源”的策略问题。

| 本轮交付 | 本轮之外 |
|---|---|
| 0.1 JSON 策略协议、manifest 策略投影、能力声明校验和 API 协商 | 发布 SDK、语言绑定生成、完整包 manifest/schema 与作者打包工具 |
| 内存中的安装元数据、能力授权、贡献点与会话管理 | 包下载/解包、签名/发布者认证、包内容摘要计算与校验 |
| SelectionRead、DocumentMetadataRead、CapturePropose 三种能力的授权判定 | 实际读取选区/文档、提交候选、入库、审核、审计与 outbox 事务 |
| 无界面调用示例及真实 Rust 回归测试 | 插件代码执行、运行隔离、CPU/内存预算、持久任务恢复 |
| 资源范围、库绑定、授权世代与旧许可失效 | 网络、凭据、账号、云服务、UI 与平台运行验收 |

F-EXT-01/03/04/06 仅完成上述策略层部分；F-EXT-05 的第三方独立开发、打包、安装、分发闭环仍未完成。EXT-B01–B08 与 EXT-P01–P13 不因这次策略实现自动通过。

## 入口与主要流程

当前入口是 Rust 宿主 API 和无界面示例，供工程验证，不提供面向最终用户的插件管理页面。宿主侧管理动作与插件侧请求分开：插件不能通过请求载荷执行安装、授予自己权限或创建受信任身份。

1. 一个宿主实例绑定一个库。宿主提供 manifest 策略投影及包摘要标识，校验标识、声明、贡献点与 API 兼容。注册成功仅表示建立内存记录，不表示包内容已认证或代码已装载。
2. 宿主与插件声明协商当前 API 和可用能力。必需能力不支持时拒绝；可选能力只有协商支持后才可进一步授权。声明和协商都不会自动创建授权。
3. 宿主根据已明确的用户范围授予能力。选区读取绑定具体库与选区标识；资料元数据读取绑定具体资料，也可单独显式授予指定库全部资料的元数据范围；提交捕获候选绑定明确的目标库。读取元数据不会赋予正文读取或候选写入能力。
4. 必需能力没有显式授权时拒绝启用；宿主启用合格安装实例，为一次运行建立绑定宿主实例、安装实例、包版本/摘要、库和授权世代的会话。调用者身份由会话确定，不能从 JSON 载荷自报或更换。
5. 请求经过 API 版本、运行状态、库、能力和资源范围检查；成功仅得到策略许可。同步分派在执行受信任宿主回调前重新验证并消费许可；本轮没有实际能力适配器，许可不代表已读取资料或保存知识。
6. 撤权或生命周期变化使相关旧会话/许可失效。停用后贡献入口不可查询为可用；再次启用必须使用新会话。升级只接受同包、同发布者且更高的包版本及不同摘要；成功后清空授权、禁用实例，须重新授权与启用。卸载移除安装记录和可用贡献。

本轮通过同步宿主可变借用与调用顺序界定策略状态变更和许可消费。未来接入并发执行、异步回调和 Core 写入时，仍须在真正提交点重新检查权限，并定义撤权与提交的序列化边界；不能以本轮同步回调证明数据库事务原子性。

### 失败、取消与离线

- 畸形 JSON、未知协议字段/枚举、无效标识、重复或冲突声明和不兼容 API 明确返回错误，不默认为成功或忽略必需约束。
- 未授权、资源不匹配、跨库、旧会话、停用或已卸载实例均拒绝调用；错误保留可判定原因。
- 安装元数据或升级校验失败时不替换有效状态；成功升级后不会沿用旧授权。申请权限被拒绝时保持未授权，不以重试补齐权限。
- 本轮不执行异步任务，因此没有可声称已取消的插件进程、I/O 或持久工作。停用、撤权和关闭会话只终止策略层的后续有效性。
- 所有策略操作均可离线运行，不发送用户资料。进程退出后安装元数据、授权与会话消失；当前不能展示“已持久安装”或“重启恢复成功”。

## 插件与宿主边界

| 归属 | 本轮职责 |
|---|---|
| extension-api | 版本化、可序列化的纯数据协议与校验；无 UI、存储、运行时或 Core 内部实体 |
| extension-host | 安装元数据与能力策略、显式授权、生命周期、宿主会话和贡献查询；普通依赖只有公开协议 |
| learning-domain | 保持无业务类型、零外部依赖；不为本轮提前制造知识实体或数据库 |
| 后续功能插件与运行适配器 | 消费同一公开协议，实际能力调用交给宿主验证；本轮尚未执行任何插件代码 |

能力目录只公开实际覆盖的三项策略能力。Command 与 SelectionAction 贡献点使用公开协议描述，按安装启停及所需能力是否已授权过滤；查询到贡献不表示当前具体资源也已授权，调用时仍需检查实际范围，也不表示 UI 已渲染或动作已执行。官方与第三方共用同一命名空间、声明、授权和生命周期规则；不得增加官方 package_id 特权分支。

安装入口接收的 `package_digest` 是未来受信任包验证器提供的标识。本轮不读包字节，不检查内容与摘要是否一致，不认证发布者；manifest 中出现名称、发布者或摘要不构成真实性证明。管理入口仅供受信任宿主装配层调用，未来不得直接暴露给不可信插件载荷。

独立包、真实第一方功能包和实际贡献 UI 验收继续按 [插件发布门槛](../architecture/extensions.md#12-第一阶段交付顺序与发布门槛) 执行。本轮普通身份的策略回归只能证明规则一致，不能替代这些验收。

## 数据与来源

安装记录、授权、会话和贡献目录归宿主运行管理；它们只存在内存，不是知识事实，也不进入知识导出或同步。库、资料、选区标识只用于授权范围核对；当前不验证对应资料或选区实际存在，本轮没有读取原文件或创建真实知识实体。未来受信任能力适配器须再核对资源存在性、归属和版本。

CapturePropose 仅表示“可提出捕获候选”的能力判定，不等于 CaptureDraft 已持久接收，更不等于正式提交知识。未来内容入库必须由 Core 验证不可变快照、出处、版本、审核、幂等与事务；本轮不改变相关设计。

停用或卸载只删除宿主策略状态，没有删除知识的接口。由于当前尚无持久知识存储，不能声称已实际验证“卸载后历史内容仍可读/引用/导出”；该要求保留为后续真实入库闭环的门槛。也不声称任何本地定位或外部精确回跳已实现。

## 可观察验收

以下场景已由本轮示例和自动化测试覆盖；具体检查与未验证范围见末尾记录。

| 场景 ID | 前提与动作 | 预期结果 |
|---|---|---|
| FND-01 协议 | 对合法 0.1 manifest/请求做 JSON 往返，输入畸形或未知字段/枚举 | 合法载荷语义一致；无效协议明确拒绝，不注入身份 |
| FND-02 兼容 | 提交不兼容 API、未知能力、重复声明或无效贡献 | 注册/协商失败；无部分安装状态 |
| FND-03 默认拒绝 | 注册插件，仅声明能力，没有授予范围 | 缺必需授权时拒绝启用；可选能力未经授权的请求也被拒绝，manifest 不产生权限 |
| FND-04 最小授权 | 授予具体选区/资料范围，另验证显式库级元数据授权 | 精确范围不扩大；库级元数据只覆盖同库资料元数据，不扩大到选区、其他库或候选能力 |
| FND-05 会话身份 | 使用宿主会话请求另一库，或在另一宿主实例复用上下文 | 拒绝跨库/跨实例访问；插件载荷不能替换身份 |
| FND-06 撤权 | 获得许可后撤权，再提交旧会话/许可 | 旧授权不能继续通过；同步分派拒绝旧许可且不调用回调 |
| FND-07 启停 | 已启用实例有贡献和会话，停用后查询/调用，再启用 | 停用时入口不可用、旧调用拒绝；重新启用不复活旧会话 |
| FND-08 升级 | 提交无效升级与有效升级，再使用旧权限/许可 | 失败保留原状态；成功后旧上下文失效、授权清空且实例禁用，等待重新授权 |
| FND-09 卸载 | 卸载后查询贡献并复用旧会话，随后重新注册同包 | 旧实例不存在或失效，新实例不会继承旧会话/权限 |
| FND-10 贡献与身份一致 | 使用不同包身份走同样注册、授权和贡献查询路径 | 不存在官方来源的授权捷径；只返回当前可用的贡献 |
| FND-11 离线与示例 | 无数据库/模型/网络运行无界面示例 | 可观察到注册、显式授权、允许/拒绝与生命周期失效；没有“知识已保存”的假结果 |

不将协议测试数量作为产品覆盖率。没有性能预算、崩溃耐久、真实 UI、原生平台、隔离或外部包结果时，均记录未验证。
