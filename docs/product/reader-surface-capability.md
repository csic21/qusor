# 公开阅读 Surface 能力验收

状态：C-08/C-09 已授权闭环的接口实施规格；公开契约与 Host registry 已实现，原生普通插件消费者已有 [本机集成资格](../../experiments/nsh-reader/plugin-surface/RESULTS.md)，不是已经发布的 SDK或正式阅读工作区。应用当前已有真实 PDF 导入、Core 页图和文字层阅读的 macOS/Android 本机子项，但尚无 opaque Surface handle、page-ready 协议或插件页图授权。关联 F-READ-01/03、F-SRC-01、F-EXT-01/03/04/05/06 和 F-DATA-01。[PDF 页图证据](../../experiments/nsh-reader/evidence/pdf-page-import/README.md)不替代正式 Surface；已有 [原生 Surface 探针](../../experiments/nsh-reader/pdf-surface/README.md) 只证明受控原生服务子项，不能作为官方插件的私有接口。

## 用户流程与功能归属

library 插件贡献资料选择，reader 插件贡献阅读工作区、页码/缩放和选区动作，notes 插件贡献个人笔记工作流。Host 承载 NSH 原生界面与授权，受控文档服务负责页图/命中，Core 持有原件、版本、摘录、回执与归档。预装和第三方使用相同 SDK、贡献点及授权链路。

用户打开资料后看到加载状态，当前页图可见后才接受选文。拖动只生成候选；确定性“保存摘录”以一次明确用户操作发起，Core 提交回执后才显示已保存。原文、来源页码与个人笔记分开；AI 正式修改仍走独立审核。保存响应丢失时查询同一 operation 回执，不创建新 operation 重复保存。

## 权限与数据边界

- 插件请求受控资料/版本的阅读呈现，不传任意文件路径、URL、NSH 节点、PDFium 句柄或数据库连接。文档范围由 Host 绑定，manifest 自报权限不等于授权。
- Surface 使用 Host 发放的 opaque handle，服务端记录所有者安装实例、会话/授权世代、vault、文档/版本与视口世代。handle 字符串本身不能替代调用者判权。
- 原生窗口输入与页图加载完成来自可信平台通道；guest SDK 不提供伪造 down/up 或 frame-ready 的入口。插件可提出页码/缩放等有界意图，不能自行声明字形、选区事实或用户批准。
- 读取当前选区仍需独立的选区读取授权；页面呈现不自动授予全书文本、原始文件、云 AI 或上传权限。选区资源只属于当前文档/Surface/世代。
- 语义原件/提取版本与临时帧摘要、窗口坐标分开。单段/复合候选使用已验证的精确锚点契约，复合内容不得只处理首段。
- Host 在异步结果交付、选区读取和最终提交时重新核对生命周期/版本/授权；现有撤权与 Core 提交的共享串行门不能被 UI 或插件绕过。

## 生命周期与反馈

打开得到 pending 会话和资源绑定；当前世代页图加载完成后才能进入可交互状态。换页、缩放、resize 或滚动按已定义规则取消活动选择，旧帧回调不能放行新页输入。新的手势不能被旧手势的迟到失败取消。

关闭工作区、停用/卸载、撤权、文档版本变化会使旧 handle 与候选失效。关闭后到达的渲染/事件结果只清理资源，不重新打开界面或恢复授权。不能确认底层资源关闭时保留明确的清理中/失败状态，不能宣称已经释放。进程重启不复活临时 Surface、选区或批准；恢复正式阅读位置必须重新打开并授权。

界面只显示用户需要的状态：加载中、可阅读、候选尚未保存、保存中、已保存、失败可重试。空白命中不弹技术异常；无文本层和不支持的选择有清楚提示。hash、token、协议与进程诊断留在日志。页图与页码/来源必须一致，不能展示旧页并标成新页。

卸载 reader 后，已收录知识仍可通用查看、引用和完整导出；停用交互工作区不删除 Core 记录。不把探针重启、内存状态或图像重新加载当成业务恢复。

## 兼容与交付条件

已有 0.1 包、签名 domain、manifest 与请求字节保持可用。新增能力必须显式协商所需协议，并按会话固定实际版本；不能直接替换 HOST_API 常量后使旧包整体不兼容。包格式、Host API、Surface 协议、锚点和归档各自版本化；需要的新能力不能混入旧会话默认授权。

| 验收 | 必须核对的实际证据 |
|---|---|
| 独立作者 | 仅凭导出 SDK 在仓库外构建普通签名包，在未改宿主里安装/运行；无内部源码、NSH 或 SQLite 依赖 |
| 身份隔离 | 两个普通安装实例相互使用 handle、旧会话/旧授权世代、其他 vault/document 都被拒绝；预装身份没有旁路 |
| 可信输入 | 真窗口触点产生服务候选；guest 构造坐标或加载完成声明不能进入可信输入通道 |
| 加载/竞争 | pending 页面不接受选择；旧 frame、旧 gesture、关闭后结果不改变后继状态；取消无知识提交 |
| 保存 | 普通插件读取完整选区并提案，一次 Core 事务保存；重复/改 payload/撤权竞争及回执查询均有结果 |
| 保留/恢复 | 停用/升级/卸载后原件/摘录仍可读导出，空库恢复后准确回源；缺原件或歧义不定位到近似句 |
| 兼容 | 原 0.1 包及请求继续实跑，新能力在未协商或未授权时拒绝；签名/SDK 仍有字节与依赖证据 |

实际窗口、普通插件、Core 持久化三条证据必须在同一旅程汇合，不能将各自通过的实验简单相加为阶段 D 完成。完整输入法、键盘/触控、EPUB、发布包和各平台仍按 [阶段计划](next-phase.md) 分别留证。
