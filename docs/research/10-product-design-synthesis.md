# 从 QUSOR 任务出发的产品设计研究与结论

后续用户纠正（2026-11-09）：对应 v0.2 整体稿被指出像 VS Code 翻版，不满足通用插件/Agent基座定位。本文参考机制保留，整体布局结论由 [基座组合研究](11-agent-foundation-composition.md) 和 [当前设计](../design/agent-foundation.md) 修正；开发稿仅是一种场景候选，不作为用户已批准的整体架构。

日期：2026-11-09。关联 C-11/C-12/C-13、F-UX-01/02、F-EXT-04/06、F-READ-01/02/03、F-NOTE-01、F-SRC-01、F-AGENT-01–05。用户要求按实际产品任务研究优秀设计，形成取舍，再精修字体、字号、整体视觉和标签页。本文补充 [第一轮研究](07-ui-ux-design-study.md)，不改变已确认的原生与插件边界。

## 研究结论

建议 QUSOR 采用**围绕工作对象组织的个人工作台**：稳定导航、对象标签、主内容、一个上下文辅助区和按需输出区共用同一套语义与视觉系统。阅读、整理、开发分别控制信息密度和工具显隐。

主要借鉴关系是：Reader 的阅读连续性，Heptabase 的资料与思考并置，Obsidian/JetBrains 的对象标签语义，VS Code/Zed 的开发分区与审查路径，Linear 的层级和对齐，Raycast 的上下文动作。它们解决不同问题；把某一款产品整体搬过来，会牺牲 QUSOR 的其他主要任务。

这是基于下列公开证据和 QUSOR 约束作出的设计判断，尚无对照用户实验支持效率提升数字。所谓“优秀参考”是选样依据，不是客观名次。

## 任务与选择标准

| QUSOR 的真实任务 | 最容易损失的东西 | 评估重点 |
|---|---|---|
| 导入、找回、连续阅读资料 | 阅读位置、正文空间、来源 | 正文优先；目录/批注按需；能回原选段 |
| 引文 → 想法 → 笔记 → 多资料研究 | 原文与观点的区别、跨对象上下文 | 可靠来源、并置参考、对象切换与布局恢复 |
| 手动写代码并交给 Agent | 未保存缓冲、项目/工作树身份、编辑焦点 | 标签、搜索、编辑、diff、终端与检查衔接 |
| 多 Agent 执行、监督、恢复和审阅 | 会话身份、实际变更、执行状态 | 任务和聊天分开；可检查成果；视图关闭不改变执行寿命 |
| 持续安装或替换功能插件 | 导航稳定、主次关系、知识可读性 | 统一入口规则、按对象适用、组件语义与状态一致 |
| 手机阅读、记录、任务跟进 | 可读字号、触控命中、返回位置 | 单主对象、层级返回、工具抽屉、未提交输入保留 |

评价顺序：完成任务与保留上下文 → 可读性和输入 → 扩展与恢复 → 扫描效率 → 外观。没有采用缺乏实测依据的竞品分数或“最快”排名。

## 对 QUSOR 的六项设计决定

### 1. 共用外壳，按任务改变展开方式

资料、知识、开发和任务是稳定目的地；实际入口来自用户固定的贡献项，不写死官方包身份。左侧局部导航服务当前工作区，内容区承载当前对象，右侧只展开一个当前辅助工具；输出区按需出现。

阅读默认关辅助区，选段或主动查看笔记时才打开；整理允许来源与想法并置；开发允许用户固定 Agent，终端按需展开。相同对象在几种状态间保留身份、位置和草稿。

### 2. 标签代表正在处理的对象

开发默认横向对象标签，便于少量文件与 diff 连续切换；研究可选择纵向标签，利用长文标题和资料分组。布局偏好按工作区保留，两种方向使用同一对象模型，避免同时复制一套相同的打开列表。

标签包括文档、笔记、代码、diff、任务；“某个插件”或“某个模型”不是标签身份。固定、未保存、同名文件路径、溢出列表、重开和关闭后的焦点均需定义。关闭任务视图不会停止任务。关闭未保存代码需要保留草稿或明确处理，不能伪报写盘。

### 3. 高级感来自文字与空间的秩序

UI 正文以 14–15、说明 12–13、代码 14/24、阅读 18/32、内容标题 24/34 起测；主信息不再使用 11–12。中文界面使用平台字体，拉丁界面可评估 Inter，代码使用独立等宽字体。中文不套用拉丁标题的负字距。

外壳采用清透的中性色，内容表面保持清楚，阅读纸色只作用于可重排正文。单一低饱和强调色标识当前状态，成功、错误和来源保持语义独立。具体紫灰色是候选，最终品牌未冻结。规范见 [视觉精修 v0.2](../design/visual-refinement.md)。

### 4. Agent 与成果检查相邻

辅助区用于会话、输入、上下文和当前进度；代码、差异、预览和任务详情可提升为主内容。任务对象持续显示项目/工作树、实际后端和能力状态。等待、失败、已执行、已验证分别表达；没有真实检查回执时显示“尚未运行”。

知识候选仍经 Core 审核/版本校验；项目文件仍走文件系统与缓冲冲突处理。两种写入不能共用一个含义模糊的“应用全部”。

### 5. 插件扩展动作与角色，不扩张常驻栏

插件声明适用对象、组件角色、动作与能力；宿主按照区域、优先级和用户固定项组装。新插件默认可被发现和搜索，不自动占据一个新侧栏或全局顶级标签。可信权限和停止入口由宿主提供。

普通提供者使用共同的字号角色、控件状态和来源组件。组件替换继续服从 [组合规格](../design/composition.md)，本研究不发布新 SDK 类型。

### 6. 手机保留任务连续性

手机默认一个主对象；资料/知识/任务等主目的地使用底部导航，目录、引文、Agent 和输出进入抽屉或详情页。打开对象从计数入口切换，返回恢复阅读位置、草稿和任务绑定。代码审阅与任务跟进可以优先设计，完整编辑、本地执行和远程连接分别验收。

## 把判断变成验收

| 场景 | 必须验证的结果 |
|---|---|
| 读到一半记录想法再返回 | 正文位置、选段和未提交输入保留；没有永久表单挡住阅读 |
| 三份资料形成一条笔记 | 并置参考不丢来源；可追溯到确定版本；原文/观点/AI 推断可辨 |
| 同名代码文件与 Agent 同时工作 | 文件路径/工作树不混淆；切换对象不抢编辑焦点；真实 diff 与缓冲冲突可见 |
| 关闭再重开对象/重启应用 | 草稿、视图与执行状态按各自寿命恢复，插件不可用时有恢复入口 |
| 安装十个功能插件 | 主内容可用宽度不随插件数下降；同类动作可检索，固定入口由用户控制 |
| 窄窗、手机和字号放大 | 区域折叠或转为详情页，文字不缩小挤入三栏；关键触控命中区至少 44 逻辑单位起测 |

常规文字对比度以 [W3C 的 4.5:1 基线](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)作为候选配色检查目标；还须检查实际状态、焦点、语义和输入，不能从一组色值宣称整个原生应用已通过可访问性验收。
