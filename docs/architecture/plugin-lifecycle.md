# 插件包、安装状态与运行恢复

日期：2026-11-07。状态：生产生命周期设计；[独立实验](../../experiments/extension-package/RESULTS.md) 已验证完整签名、显式本地键绑定及禁用安装事务。正式安装器、信任 UI、持久授权和长驻恢复尚未完成。沿用 [ADR 0003](adr/0003-plugin-first-delivery.md) 的第三方独立包与第一方同权要求，以及 [ADR 0004](adr/0004-headless-extension-policy.md) 的升级后禁用、清空授权规则。相关行为规格见 [插件安装与恢复](../product/plugin-lifecycle.md)。

## 1 目标与已有证据

让独立作者仅用公开 SDK 工件构建包；用户取得包后，可以在不重编译宿主的情况下安装、授权、运行、重启、更新、恢复、禁用和卸载。官方阅读、资料库、笔记以及后续核心用户功能复用这条链路。插件管理与恢复属于 Host 职责，不依赖某个功能插件先运行。

现有生产代码只有 0.1 协议与内存宿主策略。[Wasm 实验](../../experiments/extension-wasm/RESULTS.md) 已证明本机独立模块执行及部分预算/中止行为；包摘要只覆盖模块，未认证 manifest 或发布者，未证明安装持久化、并发替换防护或同一长驻管理进程恢复。本文中的状态与协议是后续实现约束，不能计作实验通过。

关联 F-EXT-01/03/05/06，实施拆分沿用 EXT-B02/B03/B04，验证沿用 EXT-P04/P06/P08/P11/P13；真实知识保留另依赖 EXT-B06 与 EXT-P03。

## 2 责任和目录归属

| 责任 | 目录归属 | 边界 |
|---|---|---|
| 包与能力 wire contract | 现有 `crates/extension-api/` | 权威类型、校验规则、版本兼容；不执行文件 I/O，不认证自报身份 |
| 安装/授权/会话纯策略 | 现有 `crates/extension-host/` | 唯一安装状态机和授权判定，定义 Host ports；不直接依赖数据库或运行时 |
| 包格式与验证规则 | 规划 `crates/extension-package/` | 格式/清单/兼容及身份证据规则，不维护另一份安装状态；具体文件/密码实现走适配器 |
| SDK 分发 | 规划 `sdk/` | 从权威协议导出 schema/绑定，提供文档、打包及离线验证工具；不维护另一套手写协议 |
| 包存储、安装记录、信任校验和运行实现 | 规划 `adapters/` | 实现 Host ports；与 Core 知识存储职责分开，不获得正式知识写入旁路 |
| 装配和管理入口 | 规划 `apps/` | 实例化策略、supervisor 与适配器，呈现宿主授权/恢复界面；不实现监督状态机 |
| 官方功能包 | 规划 `plugins/` | 独立构建及版本，依赖公开 SDK；不依赖 application/storage/NSH 私有实现 |
| 故障与持久化验证 | [experiments/](../../experiments/README.md) | 独立 Workspace、固定依赖、合成输入和复现脚本，验证后决定生产接入 |

supervisor 的生命周期策略由 Host 及其执行端口负责，进程监督实现位于运行适配器；apps 仅装配。详见 [统一目录架构](workspace-layout.md)。

这些是职责位置，不要求现在生成所有 crate。SDK 首次只发布实际可执行能力；包管理不提前扩展为中心市场、收费、任意插件依赖解析或跨设备自动装代码。

## 3 状态与数据所有权

| 状态 | 所有者与持久内容 | 不允许恢复或混入的内容 |
|---|---|---|
| 不可变包内容 | Host 内容存储：验证后的包字节、完整摘要、签名证据、验证器/格式版本 | 安装时输入路径不作长期执行依据；运行不能重新打开原始下载目录 |
| 安装与运行管理 | Host 状态存储：安装 ID、绑定库、发布者键绑定、当前包引用、安装修订、启用意图、授权记录、授权世代、私有状态引用、操作日志、故障状态 | 不存正式笔记/摘录/引用；凭据原文不进入普通日志/导出 |
| 活跃执行上下文 | 内存：宿主启动标识、运行会话、具体选区、文件/Surface 句柄、一次性许可、未消费回调 | 重启后全部作废，不能序列化后原样恢复 |
| 正式知识 | Core：不可变原件/快照、实体/版本/来源、提交回执、操作记录、索引工作和 outbox | 不随插件更新、回滚、清缓存或卸载删除；不由包管理存储替代 |

继续采用一个策略宿主实例绑定一个库的现有规则。包内容可按摘要在设备复用，但安装实例、授权与私有状态按库隔离；共享字节不共享授权。卸载后保留必要的安装历史/出处标识；重装创建新的安装 ID，旧安装上下文不能重新匹配。

Host 持久记录 schema、私有状态版本、包版本、manifest/SDK API、Core schema 各自版本化。生产存储库与包容器尚未选型；先在实验中验证事务、文件可靠落盘、锁和故障注入，再确定实现。不得把不同存储里的两个提交宣称为一个原子事务。

## 4 独立作者到验证工件

作者从发行 SDK 获得 manifest schema、可用能力、请求/错误/版本规范、构建打包工具、验证器和最小例子。验收时把这些发行工件复制到仓库外目录，构建依赖不能包含 QUSOR 源码路径；SDK 自身版本和内容摘要进入构建记录。

包逻辑格式至少包含：完整 manifest、运行入口、静态资产清单、每个条目的大小/MIME/内容摘要、包格式版本和签名信封。签名载荷绑定规范化清单、全部可执行/资产条目摘要、package ID、publisher ID、版本与声明权限；签名信封不包含自身。完整包标识由确定性的签名载荷和签名证据计算，具体规范化编码及算法在格式实验中固定并给出测试向量。不能只校验 Wasm 而允许 manifest、权限或资产被替换。

受信任验证器生成内部 `VerifiedPackage` 结果，包不能通过自报字段构造这一结果。它至少绑定完整包摘要、已验证发布者键、兼容能力/执行 profile、不可变内容句柄和验证策略版本；策略内核只接受宿主提供的此类可信结果。

校验顺序为：

1. 限制总输入、解包后大小、文件数、单文件大小、路径长度与嵌套；拒绝路径穿越、绝对路径、链接、重复/大小写冲突路径、未列入清单的可执行内容和格式歧义。
2. 将输入复制到宿主独占暂存区，读取同一批受控字节完成解析、摘要与签名验证。冻结后发布到按摘要寻址的内容存储；执行只消费冻结句柄或核对过的同一内容，不使用“先验路径、稍后重开原路径”。
3. 校验 API、manifest、执行 profile、必需能力、贡献点与声明大小。未知必需项或不兼容拒绝进入可激活状态。
4. 检查发布者信任与包 ID 归属，再向用户展示经验证的权限差异。签名正确、来源受信和运行隔离分别给出结论；任一项不从另一项自动推出。

验证器、解包器和运行器均有预算。解析插件提供的 manifest 不能执行插件代码。平台原子文件操作、锁与并发替换行为必须按实际平台验证；摘要和签名不构成沙箱，也不防御已经完全控制本地宿主/账户的攻击者。

## 5 发布者信任

采用本地信任记录的候选路线，不要求先建设账号、远程注册中心或市场：首次安装显示发布者标识、密钥指纹、包来源及申请能力，用户确认的是该键对该包命名空间的信任。自签名仅能证明同一键的持有关系，不声称已经验证现实身份。普通包初次信任失败则保持未安装；开发包必须显式标为开发来源，仍受全部执行与权限约束。

后续更新必须匹配已登记包 ID 与发布者键绑定，不能用相同显示名称接管。换钥使用绑定旧键、新键、包命名空间和递增修订的轮换证据，并验证旧键与新键的证明；具体签名格式随包格式一并验证。缺有效轮换证明不能当普通更新；信任修复是单独显式管理操作，不静默接受新键。撤销键或发现信任记录损坏时停止新执行，保留包和用户数据以供修复，不自动回退信任。

本地信任不等于有在线撤销服务。离线校验使用本地已知证据并明确其范围，不伪造已查询远程安全状态。生产密码库选择、密钥存储与轮换编码仍待技术验证，不在本文宣布完成。

## 6 安装和激活提交

持久状态采用“一个当前版本 + 至多一个待处理变更”的最小模型，不建立可任意并行分叉的安装工作流。操作 ID、expected installation revision 和终态回执使重复命令可查询结果；同一操作 ID 携带不同包/输入必须拒绝。

```text
取得包 → 独占暂存 → 验证内容/身份/兼容 → 包内容可靠落盘
       → 安装记录事务提交：当前包、私有状态引用、disabled、无授权
       → 用户授权及启用 → 持久授权提交 → 创建新会话 → 发布贡献
```

文件先可靠落盘，再提交安装记录引用。事务失败时未引用内容可延迟回收；不得先展示“安装完成”再尝试保存包。内容目录发布与管理事务之间可以留下孤立内容，由重启协调器安全清理；绝不能留下已确认安装却无法读取的包引用而继续执行。

安装不意味着授权，授权不意味着所有 required capabilities 已满足。激活时重新校验当前包、信任、兼容与有效授权，再创建唯一会话，成功后才发布贡献。失败保持已安装且禁用，并提供可解释原因。首次生产实现沿用显式启用；自动启动仅在已保存启用意图、包/信任/授权仍有效时重新建立会话。

关键恢复点按持久提交事实判定：

| 中断位置 | 重启后状态 | 不允许的恢复 |
|---|---|---|
| 内容尚未可靠发布 | 无新安装；清理隔离暂存 | 从下载目录直接执行 |
| 内容已发布，安装事务未提交 | 原安装保持；新内容作为未引用候选回收 | 因磁盘存在较高版本便自动选择它 |
| 安装事务已提交，尚未激活 | 新包完整已安装但禁用 | 恢复不存在的活跃会话 |
| 更新已停止旧实例，尚未提交新引用 | 原包和原私有状态仍为权威，保持禁用并标记更新中断 | 复用旧授权世代或将迁移半成品交给旧代码 |
| 更新事务已提交，响应尚未返回 | 新包与新私有状态为权威，禁用且等待授权；按操作回执显示完成 | 把“调用方没收到成功”解释为应恢复旧引用 |
| 禁用/卸载 tombstone 已提交，清理未完成 | 保持禁止执行，幂等继续清理 | 因包文件尚在就恢复运行 |

日志与当前引用在同一管理事务更新；恢复完成前不开放相应安装的激活。运行中的状态是易失观测，持久启用意图不能冒充启动成功。磁盘不足或落盘错误不得返回安装/更新成功。

## 7 重启与授权恢复

每次进程启动生成新的宿主启动标识，所有旧会话和回调失效。启动协调器先取得管理存储单写者锁、检查日志和当前引用，再开放激活入口；损坏/未知 schema、未完成替换或缺文件导致对应安装进入需修复状态，不猜测最近目录是正确版本。

持久化的是用户可持续授权的范围记录，不是运行许可：记录绑定安装 ID、完整包摘要、库、能力、资源范围、授权世代、有效期及授权策略版本。只有仍相符的记录才可用于创建新会话。当前选区、一次性文件句柄与临时用户动作授权不在重启后恢复；重新取得具体上下文。停用/撤权/升级均递增世代，世代不能回退或在恢复旧包时复用。

涉及正式写入的批准另绑定候选内容 hash、包摘要、目标实体/来源版本、批准范围、安装 ID 与授权世代。重启后的候选可以保留供查看，但旧批准不能直接驱动执行；重新校验并取得所需审核/动作上下文。包代码、payload 或目标版本发生变化时，不能沿用旧批准。对已经提交的请求只查询 Core 幂等回执，不因没有收到响应就重演写入。

## 8 更新与回滚

普通更新继续要求同包、同发布者、更高版本和不同摘要；旧策略 API 的成功升级仍清空授权且禁用，不偷偷改变为继承授权。回滚是未来独立的受信任管理命令，不能放松普通更新的版本单调性。

更新分为以下阶段：

1. 验证新包并可靠落盘；失败不触碰旧安装、授权或会话。
2. 记录待更新意图，停止旧实例接受新任务，在提交/撤权序列化边界撤销旧会话与句柄，取消或排空在途调用。不能热替换活跃代码。
3. 复制或快照当前插件私有状态，迁移到新版本的独立副本。迁移只通过受限私有存储能力执行，禁用网络、正式知识写入和 UI 贡献；超时/失败保留原副本。
4. 对新包做受限启动预检，验证加载/必需 exports/协议握手；预检不授予业务权限，不提交正式知识。运行依赖用户授权的功能行为留到正式激活后验收。
5. 管理事务原子选择“新包 + 匹配私有状态”，记录恢复点，递增安装修订/授权世代，清空授权并保持禁用；完成后提示版本与权限差异，重新授权后才进入正式激活。

在停止旧实例之后失败，恢复旧包与其匹配私有状态引用，但旧会话仍失效；保存可解释失败记录并保持禁用，由新上下文重新启用。该失败行为比验证前拒绝更保守，规格必须区分两者。

显式回滚只允许选中仍保留、重新通过完整性/信任/兼容校验的历史包，并恢复对应私有状态快照；递增世代、清空授权、重新启用。历史代码若已不兼容或信任被撤销，拒绝执行并保留修复入口。旧代码不能直接读取已升级的私有状态，私有状态快照也不能覆盖 Core。

**包回滚不回滚知识。** 新版本若已正式运行并完成 Core 提交，回滚只影响此后运行；已提交知识、操作和 outbox 保留。需要改变这些内容只能走独立 Core 撤销/编辑用例。包版本、Core schema、操作日志和外部服务副作用不共同“恢复到某个时间点”。

## 9 禁用、卸载与事务排序

禁用先封闭新调用，在共享授权/提交门内持久记录禁用及新世代，然后撤销会话/句柄、移除贡献，发出取消并回收 worker；禁用成功后旧回调不得进入 broker。终止尚未确认的 worker 标记为隔离故障，禁止替代实例开始执行，不把“已发送 kill”当作完成。资源回收错误可继续显示，但逻辑撤权不能因 worker 卡住而失效。

卸载先完成逻辑禁用，持久记录卸载 tombstone 后回收不再引用的包/缓存。是否删除私有设置由明确选项控制；移除连接授权与凭据引用，凭据本身由安全存储按共享引用处理。卸载失败或崩溃后从 tombstone 继续清理，不恢复已卸载安装；重新安装分配新 ID。Core 内容、收录回执与审计出处始终保留。

Host 管理状态事务和 Core 知识事务分开。将来真实写入必须由同一库的受信任应用服务持有共享授权/提交门：在门内复核当前安装世代、包摘要、资源版本与批准，再提交短 Core 事务。撤权/禁用在同一门内先持久化新世代后对用户确认；先提交的知识保留，先完成撤权的调用不得提交。插件和网络调用不在门或 Core 事务内运行。

这是未来跨模块协同协议，不是两个数据库自动拥有分布式原子性。实现必须规定锁顺序和单写者所有权，注入“Core 提交后进程终止”“撤权持久化失败”“Host 状态不可读”等故障；无法确认授权状态时关闭执行，未知提交结果查询 Core 回执。持久化/事务门未完成前，不授予实验真实知识写入能力。

## 10 长驻宿主故障恢复

长驻 supervisor 管理多个隔离 worker，按安装 ID/包摘要/授权世代/运行会话识别调用；任意一个插件失败不能让其旧 IPC、排队回调或资源句柄落入新的实例。worker 只通过 broker 请求能力，不直接持有数据库连接；broker 的外部 I/O 有自己的超时和取消策略。

| 故障 | 宿主行为 | 必须验证 |
|---|---|---|
| 插件 trap、预算耗尽、异常退出 | 当前任务失败，撤销会话，回收实例；保留诊断 | 同一 supervisor 中其他插件继续调用，失败插件可在新会话显式重试 |
| host call 阻塞 | 关闭该调用入口并按预算取消，必要时终止 worker；管理入口仍可用 | 超时覆盖来宾与 broker I/O，不依赖来宾主动返回 |
| kill/wait 失败或回收结果未知 | 隔离该安装，禁用自动重启，保留可观察故障 | 不并行启动同安装的新执行者；不接受旧结果 |
| 连续启动失败 | 有界重试后禁用并提示修复 | 不无限崩溃重启，不影响管理/导出恢复入口 |
| supervisor 自身退出 | 下次启动从管理日志协调，再新建会话 | 旧 worker 通道失效；残留进程处置未确认前不恢复其执行 |
| 业务提交已成功但响应丢失 | 查询相同幂等键的 Core 回执 | 不重复提交、不把已完成操作显示成已撤销 |

任务恢复只从宿主持久接管的输入/checkpoint 开始，重新检查权限、包和资源版本。新调用具有新运行标识，可以引用原业务幂等键查询结果；不能把旧会话重新标为 active。未来网络副作用结果未知时先查远端幂等状态，不能自动重放；当前最小实验不引入网络副作用。

## 当前实现进展

[ADR 0007](adr/0007-signed-package-persistence-probe.md) 采用单容器 SQLite BLOB 候选，将完整包内容和管理记录放在同一事务中；这是有界实验，不是上文独立文件存储方案已验证。首次安装、更新与卸载的提交边界已做进程终止注入；外部作者仅用导出的公开格式/API构建两版本，完整签名及键接管拒绝已有证据。全部安装保持 disabled；未实现持续授权、新会话恢复、私有迁移/回滚、长驻监督或 Core 知识保留验收。详见 [结果与未覆盖项](../../experiments/extension-package/RESULTS.md)。

## 11 最小实施顺序与证据

1. **协议与离线包验证实验（EXT-B02/B04）**：外部作者工件、完整包清单、大小/路径/字节校验、签名及本地键绑定；保持宿主二进制不变，证明独立构建和身份连续性。先支持一个明确格式，不建市场。
2. **持久生命周期实验（EXT-B03/B04）**：安装记录、不可变内容、私有状态副本、禁用/授权恢复与每个提交边界的崩溃注入；沿用已验证候选执行器，不据此宣布生产运行时定型。
3. **长驻双插件恢复实验（EXT-B03）**：一个正常插件与一个故障插件共存，验证撤权、旧回调、worker 超时和回收失败处理。双插件用于证明故障范围，不引入任意插件互调系统。
4. **生产集成与首个正式功能（EXT-B04/B06/B07）**：对应平台/profile 门槛通过后才接真实 Core 事务与官方功能；真实卸载保留/导出恢复和第一方同权分别完成 EXT-P03/P12。
