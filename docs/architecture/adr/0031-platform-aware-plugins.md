# ADR 0031：按平台选择插件实现

日期：2026-11-08。状态：采用设计，尚未实现。关联 C-14、F-EXT-07、F-EXT-01/03/04/05/06、F-PLAT-01。

## 背景

用户在讨论 Hex 语音接入后，明确要求插件系统区分 Android、iOS 与桌面，不假定所有插件通用。既有插件架构已区分运行 profile 和渠道，但生产策略 Manifest 尚无完整平台目标和多实现选择契约。

## 决定

采用稳定插件身份与贡献契约、显式平台目标、多实现包和按能力授权。允许单平台插件；同包可携带多平台实现，独立作者的替代插件通过公开服务角色发现，不直接加载彼此代码。具体设计、状态和验收见 [平台兼容规格](../plugin-platforms.md)。

兼容判断独立检查系统/架构/版本、执行 profile、分发渠道和能力。支持、就绪和授权分别处理；安装、激活、调用与恢复均重核相应条件。未知必需项拒绝，不默认通用。变更实现不得静默扩大权限或将本地处理切到云端。

采用新版本契约和包格式演进，不给旧签名包补字段或扩大旧运行资格。首次多实现切片采用自包含签名包；独立工件下载后续另验。原生平台服务归 Host，可安装功能插件不能自封原生服务；第一方同权。

## 取舍与后果

相比仅加 supported_platforms 列表，此方案可表达同平台不同渠道/能力及部分贡献可用，代价是选择、迁移和恢复状态更复杂。相比每个平台复制一套功能插件，允许共享逻辑和稳定贡献ID，也保留独立作者/实现的选择。相比强制全部插件可移植，不伪造桌面进程在移动端可运行。

Core 与知识格式保持平台无关；设备权限和代码不随知识同步自动激活。移动端普通插件执行与渠道资格仍须单独实证，首发平台没有因此确定。本轮仅设计，不承诺 Hex 或语音功能已交付。
