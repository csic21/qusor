# ADR 0028：原生工作区分区与组件提供者

2026-11-09设计增量：用户明确书库附图只用于阅读插件，基座须适配插件自有导航/工具/内容的工作区形态。沿本ADR的区域/角色/提供者分工，宿主掌握外框、可信返回、权限与恢复；书库、格式和阅读工具归插件。完整工作区呈现仍须普通包/SDK组合验证，当前 [原生工作台样例](../../../experiments/nsh-reader/native-workbench/README.md) 只验证局部外观与对象交互，不构成隔离或生产装配。

日期：2026-11-08。状态：采用设计方向，组合协议与正式UI尚未实现。用户要求先沉淀已有UI/UX研究，并明确软件分区以支持插件和组件替换。关联 C-08/C-09/C-11/C-12、F-EXT-01/03/04/05/06、F-UX-01/02；不扩展AI/云/首发平台范围。

## 决定

2026-11-09外壳细化：用户再次确认基座定位和阅读插件化，要求布局/整体交互优先。新的 [外壳候选](../../design/shell-layout.md) 区分空间、可选工作区、功能入口、对象视图与活动，建议默认单导航区及主区域，任务/Agent不作为手动工作的前置。它细化区域治理，不更改Core所有权、同权授权或资源退出协议；具体布局待评审，未新增生产manifest/SDK类型。

将区域、组件角色、组件提供者与正式数据分开。Host提供稳定外壳和受控原生能力；工作区插件定义用户流程；组件提供者按版本化角色接入区域；Core保留实体、来源、阅读位置、笔记与引用。apps只装配，不通过第一方包ID分支实现业务。

区域包括工作区导航、工具栏、局部导航、主内容、辅助面板、上下文动作和对象状态；数量、尺寸、响应布局、焦点和主题由Host统一治理。插件通过贡献目录发现，不用安装顺序抢占默认视图。兼容组件的选择由用户明确发起，可保存角色默认值及当前对象覆盖。

组件契约描述支持格式/版本、上下文、能力、动作、视图状态、尺寸/无障碍、取消与实际释放。插件通过公开原生组件和受控Surface组合，不获取NSH内部对象、平台指针或SQLite。宿主权限/信任与安全来源呈现保持可信边界；组件替换不扩大数据授权。

替换时核对数据格式与版本、处理未保存输入、停止旧实例输入并作废旧回调，按真实任务/原生释放事实管理Closing，新提供者获得新句柄与自身权限。恢复依靠Core锚点和兼容视图偏好，不恢复Session/lease/批准。失败、停用或卸载时保留知识和恢复/导出入口；不静默丢字段、跳相似原文或清资源配额。

## 版本与实施

详细分区和替换流程见 [组合规格](../../design/composition.md)，视觉与体验见 [设计入口](../../design/README.md)。这些表格尚非已发布manifest字段或SDK类型。Host API0.2的既有贡献与Surface保持兼容；新的通用角色/组合能力须通过明确协议版本、权限和独立作者包验证后实现，不暗中扩充0.2或建立第一方私有旁路。

优先用真实本地阅读旅程落一个工作区和可替换角色，逐步扩展，不预生成空插件/空crate。替换、普通身份、窄窗、焦点、错误恢复、真实资源释放与数据保留均须实际验收。C9异步监督当前改动保留待统一复验，按用户最新优先级先完成本设计沉淀；不把其诊断测试记作完整生产交付。

## 首次原生落地与下一公开契约

设计后先将真实动态阅读消费者拆为外壳、工具栏/内容/辅助区/对象状态slots、样式控件和会话草稿状态。它仍使用普通签名包的0.2 Surface/Read/Propose与真实Core回执。内部props组合不等于公开插件提供者注册；不提供虚假的组件切换菜单，也不展示尚无数据/公开能力的资料列表、阅读进度或目录。

复核确认：独立签名的`ui-composition/v1`资产能描述布局与已授权命令，但不能自动授权读取或修改用户想法。0.2的CapturePropose只提交来源候选，SelectionRead只读自身当前lease；把跨插件笔记编辑塞入它们会改变旧权限语义。因此正式可替换想法输入角色应在明确的新Host API版本中补齐，拟为0.3的`annotation.plain-text-editor/v1`：精确Draft资源、`note.draft.edit`、带expected_revision的读取/文本替换、冻结引用/来源与独立mount授权。草稿权限不写入旧profile2，不假造旧会话或另建策略Host。

首个替换验收应由两个独立普通签名提供者完成：多行输入与段落编辑/换位，共享无损plain-text/UTF-8契约；中文、emoji、空段与换行往返，旧mount/错修订/错草稿拒绝，明确保存后查询Core并恢复。Markdown/富文本、通用组件生态及该0.3接口当前均未实现。本轮原生布局只验证现有权限下可真实完成的交互，保留上述正式SDK门槛。

具体接口、1MiB文本的有界分块/原子替换、同Host临时授权、冻结来源后的保存重新判权及普通包退出验收，见 [实施契约](../../product/component-provider-contract.md)。此契约是下一实现切片，不代表0.3已支持。

实施增量：原生分区最终bundle已完成真实选文/想法/保存与空库恢复资格，窄窗被覆盖正文的Tab焦点缺陷已实测修复并封存119源。随后应用层AnnotationDrafts落位，绑定不可变来源/原capture generation/文本与保存token，使用有界分块和原Core事务；它不依赖Host/NSH，不授予权限，公开0.3组合与普通提供者仍待接线。具体代码与局部验证见上述实施契约。

0.3接线增量：临时组件mount已进入同一Host/统一持久安装映射，旧普通grant路径不接受NoteDraftEdit；Store组件库绑定没有权限副作用，每次读取重验签名资产/安装与worker事实。用户批准是仅本会话启用并挂载，不伪造旧持久enable材料。原组件资源Closing未释放不能通过更换persistentID绕配额。完整普通提供者、事件续传与真实native释放仍待验证。

公开API0.3新增有界ReplaceParagraph，应用层仅同一行/同一base合并Pending输入；拒绝不得改变原输入、上传、checkpoint或时钟。B普通签包在guest执行段落规则，经同Host/真实Store/监督worker完成20份A→B→A、保存/重开/完整恢复及卸载保留，见[资格记录](../../../experiments/capture-core/PARAGRAPH_PROVIDER_RESULTS.md)。Core/Host/原生renderer分工不变；当前无原生段落投影，不把静态ParagraphEditor描述或headless释放确认记作真实界面/释放ack。
