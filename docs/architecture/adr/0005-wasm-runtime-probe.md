# ADR 0005 用独立 Wasm 实验验证外部代码执行边界

日期：2026-11-07。状态：采用实验方案，本机执行已验证，覆盖与限制见 [实验结果](../../../experiments/extension-wasm/RESULTS.md)；未决定生产运行时。关联 C-01、F-EXT-01/03/05/06、EXT-B01 及 EXT-P04/P06/P11 的本机部分。

## 决定来源与问题

用户已批准先提交无界面策略基座，再开始独立执行实验。[ADR 0004](0004-headless-extension-policy.md) 的纯策略内核已提供协议、资源授权与生命周期；下一步需要证明真正的独立插件代码能够只经过该边界执行，并在越权、撤权、耗尽资源或阻塞时失败。

此次授权用于 M-1 本机技术验证，不授权生产运行时集成、真实知识写入、账号接入、网络服务或 UI 功能，也不替用户决定首发平台 C-04。[ADR 0003](0003-plugin-first-delivery.md) 的独立包、公开 SDK、运行隔离与渠道要求继续保留。

## 实验决定

1. 在 [experiments/extension-wasm](../../../experiments/extension-wasm/README.md) 创建独立 Cargo Workspace 和 lockfile。运行器复用已有 extension-api/extension-host，生产 Workspace 不增加 Wasmi 或实验依赖。
2. 固定 Wasmi 2.0.0 解释器作为本轮候选，Rust 使用 1.97.1。关闭 WASI，只注册 `qusor.call`，通过 0.1 JSON 请求访问受控合成选区；禁止 start 函数与未知 imports。
3. 独立作者工程只依据实验包格式与调用协议，将 WAT 编译成 Wasm；它不依赖 QUSOR 源码路径。作者实现简单前缀处理，分别构建两个版本，在同一个未重编译的宿主中加载并核对可执行文件 hash。
4. 实验目录包由 module.wasm、manifest.json 与 package.json 组成。package.json 声明 `format_version: 1`、固定入口 `module.wasm` 和 `sha256`；宿主核对模块内容摘要。没有签名与发布者信任，目录包通过不能称为安全来源安装或 SDK 发布。
5. 为总 fuel、单次切片、墙钟 deadline、取消、VM 内存/表/栈、输入/输出及 host call 设置限额。切片、调用与结果接受边界重新检查状态；取消在宿主锁内检查点生效，已先接受的结果不撤回，已完成的短同步读取不能追回。不靠无限补充 fuel 维持运行。
6. 每次 CLI 调用新建监督父进程和 worker。看门狗覆盖模块处理与宿主回调意外阻塞，达到 1,000 ms 阈值后尝试终止并等待回收 worker，另受 OS 调度及 kill/wait 耗时影响。此机制只提供故障处理，不构成 OS 权限沙箱，也不能回滚已产生的业务副作用；本轮避免真实写入和外部副作用。

Wasmi 官方提供解释执行、fuel 和资源限制接口，支持本轮机制选择；QUSOR 的配置与预算验证结果单独记录于 [本机证据](../../../experiments/extension-wasm/RESULTS.md)。依据固定的 [2.0.0 API 文档](https://docs.rs/wasmi/2.0.0/wasmi/) 和 [v2.0.0 源码](https://github.com/wasmi-labs/wasmi/tree/v2.0.0)，不以未固定的上游最新版描述替代本轮证据。

## 威胁边界与数据所有者

来宾模块和目录包声明均视为不可信输入。调用身份由宿主会话绑定，JSON 不能自报或替换安装实例、库和授权世代；未知导入不能获得文件、网络、进程或凭据能力。合成选区属于实验宿主，仅在具体范围授权后返回。插件返回字符串不是正式知识，不入库、不创建审计/outbox 或来源快照。

宿主 JSON/包读取、解释器与唯一 host call 的实现属于受信任计算基。VM 线性内存限制不覆盖全部宿主分配；fuel 不抢占阻塞宿主调用。父进程终止 worker 不能证明解释器漏洞不可逃逸、进程 OS 权限最小化、内核级总 RSS 限制或移动平台适配完成。

当前目录包只检验模块字节与声明摘要的一致性。攻击者可同时更改模块与摘要，因此它不能认证作者；签名、换钥、包 ID 接管、分发信任和完整安装恢复仍是后续独立工作。

## 通过条件与失败备选

通过条件限于实测平台：独立构建两版包，宿主二进制 hash 不变；正常选区转换得到预期输出；跨库/选区越权与撤权拒绝；死循环、超量 VM 资源、非法内存范围和超大响应受限；start/未知 imports/坏包被拒；deadline、取消有明确结果，看门狗终止后下一次独立受监护调用正常包成功。精确预算见 [实验说明](../../../experiments/extension-wasm/README.md)，实际环境、逐项结果与证据见 [实验结果](../../../experiments/extension-wasm/RESULTS.md)。

若预算/中止无法强制执行或宿主不可恢复，保留最小复现并阻止生产集成；先修正执行/调用边界，再比较其他受限解释器或执行器。若 OS 管理或渠道不支持对应方式，另做平台实验，不以仅内置、静态模板或自动移除移动首发目标替代验收。

## 对当前范围的影响

允许从纯策略进入执行不可信 Wasm 的独立实验；不将实验自动提升为正式 adapter。EXT-B01 的平台与渠道矩阵、EXT-P04 的真实事务/网络边界、EXT-P06 的完整宿主资源约束和 EXT-P11 的发行 SDK 仍分别验证，本机部分通过不能标记整项完成。未注入 kill/wait 失败，不能承诺任意 OS 故障下均按阈值完成终止和回收。

未验证范围包括长驻多插件宿主内恢复、kill/wait 失败路径、正式知识保存/卸载保留/导出、持久任务恢复、真实第一方功能插件、公开 SDK 发行与长期兼容、安全安装与更新恢复、网络/凭据 broker、NSH UI、原生 Windows/macOS 与移动运行/分发。首发平台、AI/画布/同步和云端默认选择保持原状态。
