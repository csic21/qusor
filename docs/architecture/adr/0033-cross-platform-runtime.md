# ADR 0033：共享平台契约与原生宿主装配

日期：2026-11-09。状态：实施中，平台资格未完成。关联 C-15、C-09、C-14、F-PLAT-01、F-EXT-07、F-READ-01/03、F-NOTE-01、F-DATA-01。

## 背景与决定

用户明确要求一次推进全平台。NSH 已提供 AppKit、Win32、GTK、UIKit、Android 原生后端及 Web target；此前 QUSOR 的阅读实验仍直接绑定 Linux 宿主、进程身份/父死守卫和 PDFium 运行路径，安装内核也显式拒绝其他平台。框架支持不能替代项目装配与运行证据。

本轮覆盖 macOS、Windows、Linux、iOS、Android、Web。保留同一 Core、来源/知识格式与公开插件身份；平台事实由可信宿主提供，纯兼容匹配位于协议/策略层。平台入口只装配，不复制阅读业务。原生五端继续使用 NSH native；Web 是显式构建目标，不作为桌面缺失的静默回退。

存储、文件选择/冻结、PDF provider 与运行器分别按平台适配。桌面进程拥有的 Child/内核对象与恢复后的 PID 记录不是同一种权限；没有能固定进程身份的清理路径时保持隔离，不以裸 PID kill 代替。移动与 Web 不模拟桌面进程，独立验证解释器/worker profile、宿主调用边界、取消与释放。签名和线程不等于 OS 沙箱。

## 兼容与恢复

不修改旧签名内容或放宽 Host 0.1/0.2/0.3 的语义。新增平台契约采用独立版本，显式匹配 OS、架构、渠道与执行 profile，支持、就绪、授权分开。缺少能力有具体错误，不能显示假成功或清空原有知识。迁移中保留旧授权与运行世代检查，未知终态不能启动替代执行。

## 验收

每端分别记录源码入口、锁定依赖、编译/链接、安装、真实启动、文件导入、原生输入/选文、普通签名插件调用、Core 保存、关闭重开与导出空库恢复。跨编译不等于真机运行，模拟器不等于商店分发。CI 矩阵只有实际运行完成后才构成构建证据。缺设备、SDK、签名或运行隔离资格时保留未完成项，不缩减为只有内置插件。

本机先复验固定 NSH `913fd76e1f8434ec6cdf248f4476c1ebe08af19f` 的 macOS 装配，保留 Linux 既有独立证据。上游当日主分支 `8830798b1f17421e02f458eb9e2abadb66d02875`、nightly `36b91689c1e7c38379179a56381de7ddab16c6a5` 与 macOS 文档已核对；稳定版仍为 0.4.0。没有自动升级运行基线。
