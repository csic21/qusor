# ADR 0006 明确插件优先的目录与下一阶段边界

日期：2026-11-07。状态：采用目录/架构决定，实施逐项留证。关联 C-01、C-08、F-EXT-01/03/04/05/06、F-LIB-01、F-READ-01/02/03、F-NOTE-01、F-SRC-01、F-DATA-01。

## 决定来源

在提出“插件链路与 NSH 验证并行，再以真实保存和阅读闭环推进”的建议后，用户明确同意按此推进，要求目录和架构清晰、阅读与其他核心用户功能都插件化，并允许子 agent 并行。授权推进前置实验、目录/协议设计和按门槛实施的最小本地闭环，不自动涵盖全部长期业务、云服务或发布。

## 决定

1. 采用 apps、crates、adapters、plugins、sdk、experiments 六类职责。完整目录、依赖图与 Feature 归属以 [目录架构](../workspace-layout.md) 为权威入口。
2. apps 只装配；crates 保留共享不变量/协议/策略；adapters 实现具体技术；plugins 承担用户功能；sdk 从公开契约发行；实验独立。现有三个 crate 不移动，不预生成空业务模块。
3. 阅读、资料库、笔记、知识/画布、学习、AI、同步等工作流通过功能插件交付。数据权威、事务、来源、审核、授权、完整导出恢复和必要原生服务由 Core/Host 保证，不外移至可卸载插件。
4. 第一方与第三方用同一 SDK、贡献点、运行 profile、安装和授权路径。预装不静态链接业务，不提供私有特权；跨插件协作使用公开能力与规范数据。
5. 插件独立 Workspace/lockfile/版本，SDK 可仓库外使用；生产根不吸收插件和实验，wire 只保留一份权威源。
6. 推进 NSH 最小阅读宿主前置验证和持久插件生命周期设计/实验，复用已有 Wasm 证据。以普通文本 PDF 为第一条实验/实施链，再补 EPUB，不缩减正式格式或平台要求。
7. 正式入库和阅读插件在相应存储、定位、隔离、包安装及 UI 门槛通过后实施；有真实消费者才增加模块，不能凭目录记作完成。

## 恢复与边界

Host 管理包/安装/授权，Core 持有规范知识；包回滚不能回滚知识。重启不复活旧会话、句柄或一次性批准。停用后保留通用内容查看和完整导出恢复入口。细节见 [包生命周期](../plugin-lifecycle.md)。

NSH/运行时实验失败保留结果与备选，未经验证的依赖不进入生产。可用实验环境不替代 C-04 首发选择，WSL 不代表原生 Windows/移动通过。

## 保留的产品选择

C-02 的首版 AI/画布/同步、C-03 云默认行为、C-04 首发平台仍未确定。本地闭环实施顺序和前置实验已获同意，不需重复询问是否开始。

## 验收

- 每个现有 Feature 有插件或基础设施归属，数据权威和停用行为明确。
- 实际 Cargo 成员/依赖被允许清单及目录登记检查覆盖；根不能吸收插件/实验。
- 独立 SDK、普通插件身份、卸载后保留均须实测，文档只证明设计完成。
- NSH 构建、启动、输入、阅读、定位、平台/分发分别登记，preflight 不替代运行。
