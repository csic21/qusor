# ADR 0017 复合 PDF 锚点与单一提交

日期：2026-11-08。状态：[独立本机子项通过](../../../experiments/capture-core/COMPOUND_RESULTS.md)，生产集成未通过。验收见 [复合收录规格](../../product/compound-pdf-capture.md)。

## 决定

沿现有实验 Core 与同一个 PDF Host 增加版本 2 的 PdfCompoundDraft/Request，不复制数据库、批准门或插件链路。复合锚点保留有序 PdfDraft 段、共同原件/提取身份、选择 profile 和明确的显示分隔符。逐段严格验证版本、精确范围、grapheme 和未知映射；拒绝重复/重叠，允许旋转页同页 engine 索引非单调。实际完整 envelope 同样受 4KiB 限制，不放宽旧能力预算。

Core 为全部段建立一个 capture ID、一个全局 revision、一个回执，以及同一事务内的操作、outbox 和索引任务。输入/草稿 hash 覆盖整个复合内容及顺序，幂等不忽略第二段。原子性不能通过循环单段保存模拟。

schema3 标识扩展的持久 JSON 载荷，物理表复用。旧记录的 compound 字段缺省且不输出，保留旧 JSON 与哈希。复合记录在旧 draft 字段保留首段作为明确受校验的兼容投影，完整权威锚点在 compound；投影必须等于第一段，不能单独作为完整引用使用。旧查询/解析和提案 getter 因此必须拒绝复合值，完整接口显式处理全部段。

归档仅在存在复合记录时使用版本 3；纯旧数据继续输出兼容 V2。恢复严格核对版本与实际数据，不允许 V2 隐藏复合载荷。schema1/2 事务迁移至3，不改既有实体、回执或全局序列；旧程序遇新数据库版本明确失败。

Host 的 SelectionRead、提案比较、native 批准、最终复核和 Core 提交均处理完整复合对象。旧协议或错误的整体摘要拒绝，不回退首段。原件和提取供给仍来自受控原生服务，插件不能自报布局成为事实。

## 限制

不将受限 LTR 选区 profile 宣称为全部 PDF 的 canonical 阅读顺序。多行原子收录通过也不代表 NSH 原生捕获、跨页拖动或生产 Core 通过。分隔符明确存储为呈现规则，逐段原文仍可独立核对。新增模块不进入生产根 Workspace，也不增加依赖。
