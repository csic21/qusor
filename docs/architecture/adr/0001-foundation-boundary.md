# ADR 0001 技术架构基座的当前边界

日期：2026-11-07。状态：采用的工程组织决策。产品首版范围仍待用户确认。

## 背景

用户要求先建立技术架构基座、技能和设计文档，业务功能暂不实现。现有研究已给出长期模块方案，但 M-1 尚未执行；立刻接入渲染器、SQLite 或云端会把未经验证的方案变成既定实现。

## 决定

建立一个可编译、可检查的 Cargo Workspace，只创建 learning-domain 的文档空壳。固定本地已安装的 Rust 1.97.1，提交 lockfile，禁止包发布。依赖允许清单当前为空。

保留规划中的领域、API、ports、application 和 adapter 边界；具体职责出现时再拆包，不预建所有空模块。NSH 和其他候选依赖先进入独立 M-1 实验。

工程检查覆盖格式、编译/lint、Rust 文档、依赖边界与本地 Markdown 引用。为依赖检查提供能绕过单一主机编译的反例：dev/build、别名、可选及目标平台依赖。

建立仓库级 AGENTS 和三个项目技能，引用唯一的范围/架构/研究文档，不复制工具厂商手册。

## 未决定

首版 AI/画布/同步范围、首发平台与富文本深度仍按功能确认记录处理。公开许可证、远端仓库、发布渠道、云项目均不由此 ADR 决定。

## 影响

当前 Cargo 测试没有业务用例，不能表示关键模块已经测试。三桌面 Core CI 不能表示 NSH 原生窗口或移动端成熟度。当前 Rust 固定版本在接入 NSH 前还要做兼容验证。

后续增加成员/依赖时更新允许清单、说明职责和证据；普通实现改动不必重复请求用户批准。产品行为或范围改变应更新相应功能规格。
