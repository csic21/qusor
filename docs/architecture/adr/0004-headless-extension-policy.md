# ADR 0004 先实现无界面的插件宿主策略内核

日期：2026-11-07。状态：采用；无界面策略实现及本地检查通过。关联 C-01、F-EXT-01/03/04/06；F-EXT-05 及独立包、隔离发布门槛保持未完成。

## 背景与决定来源

用户在前期材料基本齐备、其他会话继续 UI 研究时明确要求“先把我们的基座功能实现一下”。这将 [ADR 0001](0001-foundation-boundary.md) 的仅文档与工程骨架阶段推进到不依赖 UI 的基座实现；不会自动确认阅读器、AI、画布、同步或云端行为。

插件化和第一阶段第三方开发/安装/分发已由 [ADR 0003](0003-plugin-first-delivery.md) 确认。该决定的运行隔离、独立包闭环和平台/渠道门槛仍有效；当前没有足够证据选择并集成生产运行时，也没有真实知识存储用例可支撑完整 Core API。

当前可独立完成的职责是版本化协议、权限范围、宿主身份及生命周期策略。把这些规则实现为无界面、无 I/O 的内核，可以为后续实验及正式运行适配器提供同一套可回归验证的约束。

## 决定

1. 新增 `extension-api`：提供 0.1 JSON 策略协议、manifest 策略投影、API 协商、声明校验、三项能力与贡献描述。协议不暴露 NSH 对象、Rust 动态 ABI、Core 实体布局或存储句柄。
2. 新增 `extension-host`：单个实例绑定单个库，维护内存安装元数据、协商能力、显式资源授权、启停、升级、卸载、会话与贡献查询。宿主普通依赖只有 `extension-api`，不创建未使用的 application、storage 或 runtime 模块。
3. `learning-domain` 保持无业务类型、零外部依赖。两个新 crate 都有本轮可运行且可测试的实际职责，不以空壳预生成未来架构。
4. 三项初始能力为 SelectionRead、DocumentMetadataRead 和 CapturePropose；声明、协商与授权分开。选区/资料范围绑定库和相应标识，库级元数据读取与候选目标库均须显式指定。能力许可不表示实际读取或写入已发生。
5. 身份由受信任宿主创建并绑定会话。会话与许可通过不可由载荷构造的宿主上下文绑定宿主实例、安装实例、包摘要、库和授权世代；同步分派重新检查并消费许可后才执行受信任回调。停用、撤权、升级、卸载导致旧上下文失效。
6. 升级只接受同包、同发布者且更高版本和不同摘要。成功后清空授权、禁用实例，重新授权与启用；不因旧版本被批准而让新版本继承权限。无效升级在验证阶段失败，不替换当前有效记录。该内存转换不代表包文件原子切换或私有数据迁移。
7. 安装元数据中的 `package_digest` 由未来受信任包验证器提供。本轮仅绑定和比较标识，不读取/验证包字节、不认证发布者；manifest 不能证明来源。管理入口仅可供受信任宿主装配层使用。
8. Command/SelectionAction 贡献查询按启用状态和能力授权过滤，供未来 UI/命令宿主消费；执行时仍须检查具体资源范围。官方与第三方通过同一验证路径，没有固定官方 package_id 的特权分支。

具体入口、失败/离线行为、数据归属和场景验收见 [无界面基座规格](../../product/foundation.md)。

## 依赖方向与数据所有者

```text
受信任宿主装配 / 后续运行适配器
                 ↓
           extension-host
                 ↓
           extension-api
                 ↓
       serde / serde_json（JSON 协议）

learning-domain（独立、无外部依赖）
```

serde 与 serde_json 只在 extension-api 用于 wire 数据的序列化/反序列化与输入校验；宿主和示例均只依赖 extension-api，通过其校验入口读取 JSON。成员及 normal/dev/build/target/optional 入口受 [依赖策略](../../../config/architecture.toml) 约束，不能据此向 domain 开放运行时或基础设施依赖。

宿主持有运行管理状态，Core 仍是未来正式知识的唯一所有者。本轮没有正文读取、知识入库、审计、outbox、持久任务、数据库和导出；CapturePropose 只是能力判定。卸载没有删除知识的接口，但真实内容保留与导出仍须由后续入库链验证。

## 版本、错误与恢复

协议版本、包版本及授权世代分别处理。版本不兼容、未知或无效声明、未授权、范围错误、失效上下文和未启用实例返回可区分的失败，不静默降级为成功。

当前版本为内部开发中的 0.1 策略协议，未发布 SDK，后续可在更新文档和回归用例后演进；不能据此承诺第三方包长期兼容。成功升级清空权限的行为已在功能规格明示。

策略状态仅在内存中，按同步宿主调用顺序变更；进程重启须重新注册和授权，不提供持久恢复保证。未来并发能力执行、异步回调和 Core 提交必须共享明确的撤权/提交序列化边界，不能以本轮同步回调证明真实事务原子性。

## 不采用的方案

- 先创建完整未来模块图：当前没有足够具体消费者，会制造空接口与错误稳定性承诺。
- 提前接入 JS/Wasm、NSH 或 SQLite：对应技术风险尚未验证，与本轮可独立完成的权限策略职责无关。
- 仅把全部逻辑写成一次性实验：运行和渠道风险继续由实验解决；纯策略规则已有明确要求，应保留为可供未来适配器复用的库。
- 把 manifest 注册称为安全安装：没有包字节、发布者信任与隔离证据，无法证明第三方代码可以安全执行。
- 通过编译进宿主的示例宣称第三方 SDK 达标：无界面示例仅展示策略流程，不能替代独立包交付与真实第一方功能包验收。

## 对实施顺序的影响

允许在 M-1 运行时/平台结论之前，先实现并测试不执行插件代码的纯策略内核。这是对 [ADR 0003](0003-plugin-first-delivery.md) 实施顺序的局部细化，不降低 EXT-B01–B08 或 EXT-P01–P13 的完成条件。

后续按实际用例接入运行适配器、受控能力实现和完整 SDK；运行隔离与包验证先取得证据，再允许外部代码进入正式宿主。M-1 实验仍置于独立 Workspace，不把未经验证的大型平台依赖带入当前生产 Workspace。

## 验证证据与限制

2026-11-07，在 WSL Ubuntu / Rust 1.97.1 通过 35 个 Rust 协议/宿主测试、无界面示例、fmt/Clippy/文档构建、依赖边界检查、21 个 Python 反例及本地文档链接检查。测试覆盖声明与 API 协商、默认拒绝、范围和库绑定、跨宿主身份、撤权与旧许可失效、启停、升级/注销重装、贡献查询及计数耗尽。运行命令与证据范围见 [开发指南](../../development.md)。

没有执行插件代码、没有签名/摘要内容校验、没有运行隔离或资源预算，也没有 UI、外部包、持久化、真实知识保留、五平台或发布渠道验收。源码实现、构建、策略回归和平台验证分别记录，不互相替代。
