# ADR 0021：签名包格式落位单一公开权威源

日期：2026-11-08。状态：采用；纯格式、独立SDK与完整包回归通过。关联 C-08、F-EXT-01/03/05/06、EXT-B02/B04/P04/P08/P11/P13。

## 问题与决定

完整签名包、仓库外作者和持久安装实验已有本机证据，但包格式仍位于同时含 Store、监督器和运行器依赖的实验 crate。直接让作者依赖整个实验或复制一份格式会模糊边界。

新增生产根成员 `crates/extension-package`，按字节迁入现有 `package.rs`，保留格式 v1、签名 domain、规范 JSON、全部预算、错误、公开类型及验证语义。旧实验模块只 `pub use` 兼容转发，Store 仍在实验内，实际通过此生产实现验证完整包。纯格式14项测试迁入根成员，固定向量及弱键/篡改/别名/规范性拒绝路径不变。

依赖仅 extension-api、固定 Ed25519/serde/JSON/SHA-256 闭包；无 Host、SQL、文件系统、NSH 或 Wasm 运行器。安装状态、持续授权、私有状态迁移和监督不属于包格式，不因格式落位而宣称生产安装器或安全沙箱完成。业务 Core 不反向依赖包执行器。

## 作者和 SDK

两个现有 SDK 导出器均直接读取生产包源与 manifest，显式展开根 workspace 发行属性。工件内保持 `pub mod package`；作者 Cargo 依赖别名保留旧 Rust imports，实际 package 名为 extension-package。所有导出路径只指向工件内部，不引用主仓库。签名 domain 不随 crate 名称改写，签名包字节和原固定摘要保持。

本地 author 资格工具也使用公开契约别名，避免带入整个实验 Store；正式功能插件仍用独立发行 SDK。仓库外构建、能力/身份策略、完整安装/更新/恢复分别验收，不能把工具的本地开发路径解释为第一方私有 API 特权。

依赖检查继续覆盖 normal/dev/build/目标平台声明和实际闭包。生产根已经包含已验证的存储/运行适配器，因此实验旧的“根依赖列表完全不含 SQL/crypto”断言改为针对纯包权威源的闭包拒绝 Host/SQL/FS/runtime/NSH，并继续运行完整根架构守卫；作者工件仍严格拒绝这些私有依赖。

## 验证与限制

纯包源迁移前/后摘要必须一致，导出 SDK 源摘要也必须相同；14项固定格式测试已通过。两套仓库外作者构建/Clippy与完整包实验543项CLI场景（40次CLI真实退出86）通过，旧59项Rust覆盖为根14项+实验45项；另14项监督与14项异常恢复场景通过。最终真实捕获回归仍由主任务统一，实际结果记录于 [包迁移结果](../../../experiments/extension-package/PRODUCTION_RESULTS.md)。

生产安装/运行装配、公开贡献 Surface、产品阅读旅程、移动分发与其他平台仍按门槛继续，不改变 AI/云默认行为或首发平台选择。
