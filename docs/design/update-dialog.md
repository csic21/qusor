# 软件更新面板设计（v1）

更新：2026-11-11。状态：v1 已实现于生产应用 `apps/qusor`（更新检查、下载进度、安装并重启），本机自测通过普通打包应用走完整更新链；正式商店/公证签名与其它平台未验证。关联 C-17、F-PLAT-01；功能与发布方案见[发行与更新](../product/release-and-update.md)，装配见 [ADR 0037](../architecture/adr/0037-production-app-assembly.md)。

## 目标与原则

- 更新是**应用自身的事**，不是工作区内容：入口固定在宿主侧栏底部，不进入任何插件工作区。
- 只展示真实状态：当前版本来自应用自己的 `nsh-updater.json` 资产；可用版本来自运行中的更新源。不伪造“检查中”动画，也不在开发运行里假装有更新。
- 用户可停留：“检查更新”和“下载并安装”都只由用户动作触发；下载前不自动重启。
- 失败要说清哪一步失败（检查、下载、安装），保留当前版本继续可用。
- 端口/密钥不进入界面：面板不显示令牌、路径或签名细节，只显示版本、说明与进度。

## 入口与布局

侧栏底部：

```text
┌──────────────────────────────┐
│ 搜索工作区…                   │
│ …工作区列表…                 │
│                              │
│ ──────────────────────────── │
│ ↑ 软件更新            0.1.0  │
│ 原生界面研究          ☾      │
└──────────────────────────────┘
```

面板为窗口内浮层（`Dialog`，470pt 宽，顶部 120pt，水平居中），不动主工作区布局：

```text
┌────────────────────────────────────────────┐
│ ↑ 软件更新                            ✕    │
│ ────────────────────────────────────────── │
│ 当前版本                                    │
│ QUSOR 0.1.0                                 │
│ 已是最新版本。 / 正在检查更新… / 发现 0.1.1 │
│ ┌ 新版本 0.1.1 ───────────────────────────┐ │
│ │ 说明（最多四行，超出截断）              │ │
│ └─────────────────────────────────────────┘ │
│ ▓▓▓▓▓▓▓▓░░░░░░  下载进度（下载/安装时）     │
│ [检查更新] / [下载并安装] / [打开下载页]    │
│                   更新源 csic21/qusor · …   │
└────────────────────────────────────────────┘
```

## 状态与动作

| 状态 | 文案 | 动作 |
|---|---|---|
| 未检查 | “从应用自己的更新源检查新版本。” | 检查更新 |
| 检查中 | “正在检查更新…” | 检查按钮禁用 |
| 已最新 | “已是最新版本。” | 检查更新 |
| 有更新 | “发现新版本 0.1.1。” + 说明 | 下载并安装 |
| 下载中 | “正在下载更新…” + 进度条 | 按钮禁用 |
| 安装中 | “下载完成，正在安装并重启…” | 按钮禁用；成功路径由平台重启接管 |
| 检查失败 | “检查更新失败：<原因>” | 重试 |
| 安装失败 | “安装更新失败：<原因>” | 重试检查/安装 |
| 不能自替换 | “当前安装位置不能自行更新；已打开下载页。” | 打开下载页 |

“下载并安装”是一条路径：下载并校验 → 替换 → 重启；`installAndRestart` 只在失败时返回，因此成功时本进程被替换，不再有“完成后”界面。不能自替换时（iOS/Android、只读安装位置）只打开下载页，不下载归档。

## 可见性

- 版本号同时出现在侧栏行尾与面板正文（构建号本轮不上屏，避免与证据截图不一致）。
- 进度条只用一条 4pt 高、语义 token 着色的水平条，不做百分比动画或粒子。
- 更新说明是更新源提供的文本，按纯文本显示，最多四行。
- 更新源在面板底部标注（`csic21/qusor · GitHub Releases`），不展示私有 URL。

## 自测入口（证据专用）

本机自测需要可重放的窗内证据与机器记录，因此应用内有一个只在证据模式下生效的驱动：环境变量 `QUSOR_UPDATE_EVIDENCE` 指向收据目录时，应用自动打开面板、执行同一套检查/下载/安装路径，并在每个状态留 JSON 收据；替换后的新版本通过应用数据目录中的一次**一次性标记**识别自己是重启后的构建，报告版本、数据目录与 Core 可读性后退出。普通启动没有该变量也没有标记，不会写收据、不会退出，也不会改变界面行为。面板本身与按钮路径不依赖证据模式。

## 不覆盖

- 商店/公证签名、Windows/Linux 替换、GitHub Releases 实际拉取、移动端只能跳转商店/OTA 的语义。
- 下载中断续传、带宽限制、代理与离线错误分类的界面细分。
- 键盘路径（Esc 关闭、Tab 到按钮）与辅助技术朗读未逐一截图；`Dialog` 自带焦点与 Esc 行为，但本轮未单独验收。
