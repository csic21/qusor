# 原生视觉方向：石墨工具区与内容舞台

2026-11-09后续视觉依据更新：用户已指定 T3 Code、macOS 自带应用和 Plannotator。最新组件与实窗候选见 [原生工作台 v0.4](native-workbench.md)；本页石墨/纸张方向留作历史探索。书库附图仅用于阅读插件，基座适配其工作区形态。

状态：2026-11-09 原生视觉候选，待用户评审。关联 F-UX-01/02、C-09/C-11/C-12。依据 [作者作品研究](../research/12-native-software-design-study.md) 与用户本轮对 Web 感的明确否定；旧 v0.1/v0.2 和 HTML 稿不再作为已接受的视觉方向。

## 视觉主张

窗口像一件精细、稳定的工作工具。框架采用低饱和石墨与暖灰，主内容保持清楚的阅读对比；少量色彩标识内容种类和选择状态。工具触感来自尺寸、边缘、按压和反馈的一致性，不来自大面积装饰渐变。

Things / Reeder 是桌面秩序的主要参考，Mela 用于内容排版，Kino 用于局部控件精度。独立风格来自 QUSOR 的任务与插件组合需求，参考产品的功能模型不进入宿主。

## 字体和空间

当前 [NSH 样例](../../experiments/nsh-reader/native-design/README.md) 使用平台系统字形，中文由系统回退。以下为原生点值候选，不是把网页 px 换一种写法。

| 用途 | 字号 / 行高 | 规则 |
|---|---|---|
| 工具栏、列表与菜单 | 13–14 / 21 | 中等密度；主标签保持可读，不靠加粗全部文字强调 |
| 次级说明 | 12 / 18 | 只用于元信息，不承担核心任务说明 |
| 正文 / 输入 | 16 / 28 | 编辑与显示的字形尽量一致；长阅读另按阅读流程测量 |
| 段落标题 | 17 / 26 | 通常 600 字重 |
| 文稿标题 | 26 / 36 | 只用于内容标题；应用顶栏保持紧凑 |
| 代码 | 14 / 27 | 系统等宽候选；中文回退与混排需另测 |

样例工具栏 52pt，侧栏 230pt，按需检查器 260pt，文稿内容面最大宽度 790pt。共享工具控件高 30pt，分段标签高 31pt；触屏目标不能沿用桌面尺寸，至少采用 44pt 的操作区域。字号放大和窄窗优先减少同时显示的区域，不压缩正文维持多栏。

## 材质与颜色

颜色集中于 [运行主题](../../experiments/nsh-reader/native-design/theme.json)，共享控件集中于 [ui.tsx](../../experiments/nsh-reader/native-design/ui.tsx)。这是隔离样例的实际 token；正式宿主主题仍待装配。

|---|---|---|
| 工作舞台 | `#EFEEEA` | `#1C1F1D` |
| 工具栏 | `#F5F5F1` | `#272B28` |
| 文稿内容面 | `#FFFEFC` | `#2D312D` |
| 主要文字 | `#2D302D` | `#ECEEE6` |
| 次级文字 | `#6B7069` | `#B1B9AC` |

| 焦点 | `#467BBD` | `#93B7ED` |

纸面只用于适用的文稿和阅读 Surface；流程、画布、代码与其他插件内容各自采用适合的承载方式。样例复用的纸面框架不构成生产要求。常驻工具区与内容面保持清楚边界，菜单浮层才使用局部模糊与阴影，避免每层都玻璃化。

列表行保持连续；选择态贴合整行，不增加多余容器。常用按钮使用小范围连续圆角、轻微边缘和明确按压态；图标采用一套 24pt 网格的原创 NSH Canvas 线形，避免混用 emoji 充当控件。

## 原生窗口与组合

macOS 样例使用真实 AppKit 窗口、系统窗口按钮与原生拖动区。通过 `titleBar().left/right` 为平台控件留出空间；Windows/Linux 需要各自实测，不能绘制一套 macOS 假交通灯到所有平台。Web 目标有独立的平台适配规则，不反向规定原生窗口的层级与密度。

保留 [区域 / 角色 / 提供者](composition.md) 的职责区分。任务导航来自宿主统一组合；主内容可替换；检查器默认收起；Agent 接入菜单靠近当前任务。界面样例中的四种场景只是自拟 fixture，不是四个已安装插件，也不是新增 SDK 贡献类型。

标签属于同一任务的不同工作内容。切换标签保留该任务草稿；切换任务不得带入另一个任务的草稿。关闭视图不应隐式停止真实执行；本样例没有实际执行器。

## 显示与验收

本轮已有 [macOS 实窗证据](../../experiments/nsh-reader/evidence/native-design/README.md)，构建与显示通过，输入和局部切换已有实际结果。键盘完整路径、原生浮窗、中文组合输入、读屏、动态字号、触控、其他平台及正式数据恢复不据此通过。

正式功能仍需在同一真实流程里检查视觉、交互、数据与恢复。源码中的 hover/pressed/focus 样式只是实现；未经触发观察的状态继续保留为待验证。用户评审前不把本方向写成最终品牌或已批准方案。


## 阅读入口与跨端增量

用户随后指出缺少选择书籍与文本的路径，原生样例已按[阅读流程](reading-workspace.md)补齐书架与窗口内文字阅读。长期操作与插件安放统一按[六端基座规则](cross-platform-shell.md)；单个平台截图不能作为其他平台资格。
