# 本地阅读工作区规格 v0.1

关联 F-LIB-01/03、F-READ-01/02/03、F-NOTE-01、F-SRC-01、F-DATA-01、F-UX-01/02。这是正式本地闭环的目标规格；当前技术探针与各功能实现程度分开验收。样式采用 [设计基础](foundations.md)，组合边界采用 [软件分区](composition.md)。

## 资料库：找到下一份要读的资料

左侧为工作区导航，主区由标题/导入入口、搜索筛选、继续阅读和资料列表构成。继续阅读展示最近资料、当前章节或页码和已有进度；进度必须来自持久记录。列表展示标题、类型、最近阅读与处理状态，封面仅作辅助，不用大卡片降低中文标题的可扫描性。

主操作称为“导入资料”；PDF先行、EPUB随后，支持状态如实显示。导入不默认上传原件。空资料库解释支持格式并给导入入口；没有资料时不展示假书目、假进度或云登录要求。搜索与筛选保持在资料语境内。

## 阅读：正文先获得空间

进入资料后，全局导航收起，顶部保留“返回资料库”、文档标题、目录与摘录/笔记入口。翻页、页码、缩放或适合宽度组成紧凑阅读控制；资料导入不作为正文工具栏最强动作。长标题可省略，但完整标题与来源可查看。

默认关闭辅助面板，工具按需出现。目录可打开并保留章节位置；高频阅读动作有可见入口。AI不默认出现，未确认的云、画布等功能不塞进工具栏。

PDF保持原始版式，提供适合宽度/整页与手动缩放。手动缩放后不因面板开闭擅自重置倍率；适合宽度模式可重新计算，但围绕当前来源锚点保持阅读位置。EPUB的字号、行距与版心通过重排恢复同一文本锚点，不用像素位置替代。

## 选段：先给轻量动作

选区稳定后在附近显示“保存摘录”“写想法”和更多菜单，避免遮住选中文字和拖动手柄。键盘或辅助技术也能打开相同操作。滚动/取消选择时按当前选区生命周期处理，不让旧浮层操作下一份资料。

直接“保存摘录”是一个确定动作，正常情况下不增加重复确认；持久回执后才标记已保存。插件构造候选和宿主验证属于内部过程，界面不展示候选 ID、协议名或授权世代。

## 写想法：原文与自己的观点各有位置

用户选择“写想法”后打开辅助区：顶部为来源标题与页码/章节、“回到选段”；引用块只读；其下为“我的想法”编辑区及就地状态、保存操作。编辑焦点进入想法输入，原文仍可核对。来源、引文和个人观点不合并成一段文字。

打开编辑区前，在有效选区与权限下冻结引用草稿的来源版本和精确定位。面板变化可能使原生手势/选区句柄失效，草稿仍须稳定可核对；提交时重新核对来源版本与权限，不持久化临时lease或复用旧mount票据。现有契约若不能承接，先补公开草稿/状态契约，不能用一段裸文本伪装精确引用。

保存中保留输入并防止重复提交，正文是否可操作按保存对象的真实生命周期设计，不粗暴冻结整个软件。保存失败保留草稿，提供原样重试；结果未知先查询原回执，不生成重复摘录。成功时显示一处“已保存到本机”，提供“继续阅读”和查看已存内容的自然路径；再次编辑后恢复保存动作。

草稿在当前会话内保留是已验证能力。跨退出恢复草稿是后续实现目标，需要明确数据契约和真实落盘验证；界面不得提前承诺。离开有未保存内容时清楚说明影响，取消离开后位置、选区和输入保持。

## 笔记与回源

笔记列表按标题/来源组织，引用块显示作品、页码/章节和可操作的回源入口。点击后经可信来源解析打开相应阅读提供者并定位；版本不符、多个匹配、原件缺失分别呈现，不用相似文字假装成功。缺少高级阅读插件时先保留本地摘录与想法，提供原件导出及选择兼容组件的入口。

完整导出/恢复有真实步骤和结果：选目录 → 导出/恢复中 → 校验结果；保留原件、引用和想法。其功能插件与宿主恢复兜底分工沿用现有架构，不用 UI 直接写库。

## 状态与恢复

| 状态 | 界面行为 | 焦点/恢复要求 |
|---|---|---|
| 导入中 | 当前资料保留；显示文件级进展与可用取消 | 不抢走正在编辑的内容 |
| 文件损坏/超出支持范围 | 给具体原因及重试/换文件入口；原资料与草稿保留 | 不清空当前工作区 |
| 已导入但阅读组件失败 | 如实区分资料已保存、阅读尚不可用；提供重试/选择组件 | 不能提示完整导入失败并让用户反复重复导入 |
| 页面加载/失败 | 在页区域显示状态与重试，不拿旧图接收新选区 | 旧回调不改新对象；输入仅在当前帧就绪后接入 |
| 保存中/失败/未知 | 状态贴近想法，保留输入，原请求可重试/查询 | 不让通知抢焦点或静默关闭编辑区 |
| 已保存 | 就地确认一次；继续阅读入口清晰 | 不强制跳回页首或切换资料 |
| 来源缺失/版本不符/歧义 | 保留摘录；明确可达范围及恢复操作 | 不自动选相似文本 |
| 插件停用/组件不兼容 | 已存内容仍可读；选择兼容提供者/导出 | 新提供者不自动获得旧插件权限 |
| 旧组件仍在关闭，资源额度不足 | 显示“阅读组件暂未就绪”，保留资料与会话内草稿，提供重新检查或返回入口 | 重试不承诺立即释放；不靠重复导入、重装或删除记录腾配额；离开时处理未保存内容 |

## 窗口尺寸与焦点

数值为初始设计目标，必须用原生窗体验证：

- 宽度≥1280：可同时打开目录（约224）与想法区（约336），正文至少560；不足时先折叠辅助区域。
- 1024–1279：主内容加一个按需工具区，工具宽约320；目录和想法区按任务切换。
- ＜1024：阅读与编辑使用单任务视图，返回后恢复同一选段；窄窗不硬塞三列。
- 系统字体放大优先改变布局，触控目标至少44；PDF横向溢出提供原生滚动与明确缩放方式。

关闭辅助面板回到原选段或触发按钮。保存成功不擅自移走输入焦点；异步结果不改变焦点。`Esc`只处理最上层临时工具；未保存内容不得因此消失。快捷键遵循平台习惯，并在可见菜单中显示。

## 功能插件与公开能力

资料流程归library、阅读归reader、想法/引用编辑归notes、导出向导归data-transfer。Host负责分区、主题、焦点、原生文件选择、权限与资源；Core负责实体、版本、位置、正式写入与导出。提供者可以替换，数据不随 UI 组件迁移。

现有公开Surface不足以交付全部工作区。后续补导入/资料列表、持久阅读位置、笔记/引用列表和编辑、来源路由、组件组合契约；按公开版本与同权SDK接入，不在临时代码里按第一方包名直连Core。Markdown与富文本的首版深度仍待确定，替换契约先保证格式兼容和数据保真。

逐段/全文编辑及A→B→A替换的具体状态见[想法编辑与提供者切换](paragraph-editor.md)，与普通插件执行链一起验收。
