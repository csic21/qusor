版本：v0.3 研究候选；2026-11-09。关联 C-07/C-11/C-12/C-13/C-15/C-16，F-EXT-01/04/06/07、F-UX-01/02、F-PLAT-01、F-AGENT-01–05。

## 1. 一页能够回答的四件事

用户始终能判断：我在哪个空间、正在处理什么、当前动作影响谁、怎样返回原工作。

| 用户概念 | 意义 | 界面上的位置与限制 |
|---|---|---|
| 空间 | 组织相关内容与工作；不自动等于文件目录或授权边界 | 外壳空间切换器；切换不授予插件读取权限 |
| 工作区 | 一组打开对象、视图组合和布局偏好 | 默认已有一个，不要求命名或创建；需要多组工作时才显式管理 |
| 功能目的地 | 插件提供的集合或工作入口，例如资料库、流程列表 | 全部功能/搜索可发现；用户固定后出现在导航，不按安装数增长 |
| 打开的对象/视图 | 当前正在看或操作的文档、集合、会话、表单、流程或成果 | 主区域标签/手机对象切换器；标题不是身份，允许同名对象 |
| 后台活动 | 导入、计算、Agent 执行等具有真实寿命的操作 | 稳定活动入口与实际数量；没有活动时不以“未连接”常驻占位 |

任务是需要目标、执行或协作时的对象。直接阅读、手动编辑或查看表格不必先创建任务，也不必连接 Agent。业务对象模型和持久化继续按现有 Core/插件契约决定，不因这些用户概念预生成新 crate。

## 2. 基本布局与主次

```text
窗口 / 平台系统区
┌──────────────────────────────────────────────────────────────┐
│ 空间 / 工作区        搜索、打开或执行…                活动    │
├──────────────┬───────────────────────────────────────────────┤
│ 导航范围     │ 对象标签 / 打开的视图                          │
│ 空间｜当前内容├───────────────────────────────────────────────┤
│              │ 当前对象与适用操作                            │
│ 由范围决定   ├───────────────────────────┬───────────────────┤
│ 的目的地或   │ 主区域                    │ 支持视图（按需）  │
│ 目录/文件树  │                           │ 目标始终明确      │
│              │ 文档/表格/画布/会话/表单… │                   │
│              ├───────────────────────────┴───────────────────┤
│ 扩展 / 设置  │ 输出（按需）；内容状态靠近对应对象             │
└──────────────┴───────────────────────────────────────────────┘
```

区域表示可用职责，不表示默认全部显示。初始只显示一个导航区和一个主区域；正文、表格、画布、代码、会话由各自内容承担，不统一套纸面、卡片或窄版心。空工作区总览提供最近打开、固定功能和有实际记录的继续工作，不伪造书架、任务或 Agent 结果。

### 导航区只保留一个默认位置

- 顶部明确选择“空间 / 当前内容”。空间范围展示总览、用户固定功能与工作区；当前内容范围展示目录、文件树或当前集合导航。
- 空间/当前对象身份不会因范围切换消失；全局搜索、空间切换和活动仍可达。没有局部导航的对象不展示空目录。
- 用户主动打开目录/文件树时切到当前内容范围；返回空间范围恢复上次选中位置。插件不能自动隐藏/展开整个应用侧栏。
- 阅读目录与全局功能不各建一栏；需要同时查看两种导航的高级布局以后独立验证。
- 这是降低默认分栏复杂度的候选方案。若范围切换在可用性测试中造成明显迷路，应调整，不以“基座”之名强迫用户接受。

### 并排对象与支持工具分开

两个可以独立操作的对象使用两个主视图组，例如资料与文稿、两个版本或代码与应用预览。属性、目录、评论和选区操作通常是支持工具；它们显示作用目标，可以“跟随当前”或“固定到某对象”。

支持视图默认一个当前工具；第二个工具先在同一区域切换，而非自动新增一列。工具需要长期独立工作时，可明确“在主区域打开”。移动已有视图必须保留其状态；若原生实现只能重建，按实际释放/新 mount 协议进行，不以换位置规避回收或重复获取输入。

Agent 对话可以占完整主区域，也可以在用户请求时辅助当前对象。任务输出属于活动/输出，不能因为正在运行就强制抢占当前文稿或焦点。

## 3. 空间预算与收敛规则

以下为默认字号下、待原生验证的逻辑点初值。真实最小宽度取宿主基线与提供者声明/测量需求的较大值；字体放大、触控和可用高度会改变结果。

| 区域 | 最小 / 默认 / 最大 | 余量分配 |
|---|---|---|
| 导航区 | 184 / 208 / 280；收起后 56 或完全隐藏 | 全局与局部默认复用，不相加 |
| 主视图 | `max(480, provider_min)` | 优先获得剩余空间；480 不是长文版心或所有插件的保证 |
| 支持视图 | 280 / 320 / 440 | 可调整；宽度不足转独立页或明确覆盖呈现 |
| 双主视图 | 两个主视图各满足自己的最小值 | 默认均分后允许调整；不合格时保留活动组并提供另一组切换 |
| 输出 | 候选最小 144 高、默认 208 高 | 同时保证主区域可工作；空间不足进入活动详情页 |

约束为 `W >= 导航宽度 + Σ可见视图最小宽度 + 分隔线`，高度同样核算。不能先固定三/四栏，再靠截字或缩小字体使它们看起来放得下。

| 可用宽度示例 | 实际可分配组合 | 行为 |
|---|---|---|
| 1440 | 导航208 + 主910 + 支持320 + 两条1pt分隔 | 用户打开支持工具后可并置；支持区未打开时主区1231 |
| 1280 | 导航208 + 主750 + 支持320 + 两条分隔 | 同上；两独立主视图不再同时保留这个支持区 |
| 1100 | 收起导航56 + 主722 + 支持320 + 两条分隔 | 用户刚打开支持工具时可采用；原本只看主内容时不主动展开工具 |
| 800 | 收起导航56 + 主743 + 一条分隔 | 支持工具进入有返回的独立页；不把主区压到422 |
| 390 | 一次一个活动页面 | 系统导航、对象切换器与工具页；不显示桌面缩略多栏 |

这些是算例，不是按宽度硬编码所有平台行为的断点。提供者最低宽度更大或字号放大时，必须更早收敛。

收敛顺序：保留正在输入的对象与目标 → 把次要操作放更多菜单 → 减少导航占用 → 将非活动支持/输出收起 → 双主视图切换为一个活动组。刚由用户主动请求的工具比闲置区域优先；若焦点正在工具中，转页后继续该输入，并保留明确返回。不要在拖动窗口时反复弹出自动遮罩；恢复变宽不抢焦点、不覆盖用户手动选择。

## 4. 打开、切换、返回和关闭

| 意图 | 默认结果 | 需保留与不能发生的事 |
|---|---|---|
| 打开已有对象 | 同工作区同对象同呈现模式优先激活已有视图；无实例才新建标签 | 保留原位置/输入；同名对象显示来源辅助区分 |
| 明确另开视图 | 新视图实例绑定同一对象，按该对象支持的多视图规则工作 | 不复制正式数据，不绕过单写入/输入租约；不支持则说明原因 |
| 从集合选一个对象 | 在该集合的详情位置打开；需要长期保留时明确“在新标签打开” | 当前详情有未提交输入时不得被另一项静默替换 |
| 并排打开 | 将对象放入另一主视图组，当前对象仍在 | 空间不足则说明并提供组切换，不悄悄关掉现有内容 |
| 切换标签 | 激活目标视图及其局部工具栏/历史 | 不重新运行任务，不清草稿，不把两个独立对象的滚动位置混用 |
| 返回 / 前进 | 当前视图自己的导航历史回退/前进 | 切换标签不塞进局部历史；返回不关闭标签，不停止执行 |
| 关闭标签 | 关闭该视图；最后一个关闭后进入总览 | 不删除对象；有未持久化输入时先解决保存/放弃/取消 |
| 隐藏工具 | 保留其目标与允许保留的局部状态，归还焦点 | 不自动停止后台活动；占用资源按实际生命周期处理 |
| 停止活动 | 发送该执行提供者支持的真实停止请求 | 收到确认前显示停止中/结果未知；不以关闭面板假装停止 |

“跟随当前对象”的支持工具在没有未提交输入时才更新目标。开始输入即绑定当时对象/版本；切到别的标签时仍显示原目标，提供保存后切换/返回原对象等动作。禁止把写给 A 的文字提交到 B。并排时以明确的活动组为上下文，不以鼠标最近经过区域推断。

跨插件动作先明确对象引用、版本/选区范围和目标能力；点击“交给 Agent”或“在另一个工具打开”不默认为另一个提供者授予所有可见资料。支持视图显示选中文本不自动扩大出站或持久授权。

## 5. 命令、搜索与反馈

- 一个全局入口用于搜索对象、发现功能和执行命令，结果分组并注明范围；局部列表用“筛选当前列表”，正文查找用“在当前内容查找”。快捷键与可点击入口并存。
- 外壳动作作用于窗口/工作区；对象动作放对象工具栏；选区动作靠近选区；某一行的动作放该行菜单。插件不得把同一命令复制到三处并呈现不同可用状态。
- 各视图只保留完成当前工作需要的常用动作，其余进入明确的更多菜单；不可为了“极简”把唯一主要动作藏入右键菜单。
- 视图打开、功能安装、能力启用、资源授权、执行开始、正式保存是不同状态。常规布局调整可撤销/重置，不弹重复确认。
- 成功已能从内容/选择态看到时不重复 toast；错误靠近相关对象，后台需要处理的事情集中到活动，不每条日志弹通知。
- 活动在运行、等待用户、停止中、结果未知、完成/失败之间如实变化。关闭会话后的继续能力按真实平台/后端协商；不能承诺所有平台退出应用后仍在后台运行。

## 6. 焦点、输入与移动端

标签列表区分焦点与当前激活。加载明显有延迟时，方向键先移动焦点，Enter/Space 激活；快速视图可用自动激活，但不能每次方向移动都启动插件任务。关闭当前标签后焦点回到相邻标签或总览的逻辑目标。

快捷键提供导航范围切换、打开对象、标签/组切换和面板开合；具体按平台菜单惯例确定，不占用中文输入法组合键。区域、标签、菜单和分隔调整均有可访问名称和无鼠标替代，拖动只是快捷操作。

Esc/系统返回先由当前输入法/控件处理，再关闭最上层可关闭浮层，再处理局部导航；不得用一条全局 Esc 同时取消组合输入、丢草稿、关工具和停止 Agent。浮层关闭回到触发控件，背景不可交互时也从可访问树中隔离。

手机保持“空间目的地 → 对象 → 工具”的导航语义；对象切换器与主要目的地切换分开。若使用底部导航，只放少量稳定目的地，打开文件、停止任务等动作不伪装成目的地。安全区、系统返回、软键盘、动态字号与触控独立验证。Web 将视图路由映射到浏览器历史，不让内部标签切换污染所有页面的后退栈。

## 7. 插件接入与增长

候选贡献职责包括入口、对象视图、支持工具、命令、活动呈现和布局预设；同一个包可以贡献多项。不是强制六种包类型，更不是已经新增的 manifest 字段。

接入资料需明确：稳定贡献身份、可处理对象/格式、命令作用域、最小空间、紧凑呈现、状态/恢复版本、焦点入口/出口、取消与释放事实。宿主据此仲裁位置、实例数量、溢出、恢复和平台可用性。

| 生命周期 | 界面行为 |
|---|---|
| 安装成功 | 进入全部功能/命令目录；可选择固定，不自动展开视图、改变默认布局或运行代码 |
| 固定入口 | 用户决定顺序；超过可见空间仍可搜索/进入完整列表，不无限增加图标轨道 |
| 提供者更新 | 不自动迁移草稿格式/继承权限/替换正在输入的视图；按现有兼容/授权链核对 |
| 视图崩溃 | 隔离当前区域，保留对象身份、其他区域和输入；可重试、选兼容视图或导出 |
| 停用/缺失 | 显示原对象和提供者状态，保留替代/恢复路径；通用查看仅保证已收录 Core 的规范内容，不承诺读懂任意私有插件格式 |
| 布局预设 | 预览结构后应用，可撤销；不能关闭未解决的脏视图、抢输入或授予权限 |

信任、授权、停止和恢复界面属于宿主。插件不能另画全局导航、伪装保存成功或覆盖平台窗口控件。新通用契约仍需版本化、独立作者包及同权验证；内部 TSX import 不构成公开 SDK。

## 8. 保存与恢复

| 状态 | 所有者与恢复规则 |
|---|---|
| 正式知识、来源、笔记/引用 | Core 既有版本与事务；只有持久回执确认后标已保存 |
| 项目文件/其他业务对象 | 对应公开服务与插件契约；不强行全部装进知识模型 |
| 打开对象、视图模式、布局、宽度、支持工具绑定 | 版本化界面偏好，恢复时按现有窗口和安装/能力重验；不能直接复活旧会话 |
| 未提交输入 | 按该组件实际草稿契约；无耐久实现不得承诺退出恢复，关闭前给出真实选择 |
| 焦点、原生句柄、临时选区、授权票据 | 运行态；不作为布局存档，重开重新取得 |

重开顺序为校验空间/对象引用 → 恢复结构偏好 → 解析当前可用提供者 → 重新判权 → 恢复允许的局部状态。某插件缺失只影响对应视图，不让整个窗口恢复失败；不自动重放有外部副作用的活动。

## 9. 可观察验收

全部为待执行场景。静态图、计算、源码走查和原生/普通插件资格分别记。

| ID | 场景 | 通过条件 |
|---|---|---|
| SL-01 | 无阅读插件/无 Agent 配置进入 | 总览及通用操作可理解，没有假书架或“必须连 Agent”阻断 |
| SL-02 | 直接打开资料，再打开表格/流程 | 不要求建任务；两者有真实独立视图，返回身份/位置不丢 |
| SL-03 | 在阅读、表格、开发、会话间切换 | 主交互实际不同；不是换标题，外壳的打开/返回/关闭一致 |
| SL-04 | 两独立对象并排，再打开支持工具 | 主区域最低空间成立；工具目标和活动组可判断，超限有明确收敛 |
| SL-05 | 给 A 写评论时激活 B | 输入仍绑定 A，不能提交给 B；用户明确处理后才切换目标 |
| SL-06 | 返回、关标签、隐藏工具、停止活动 | 四个动作可区分；未保存与停止未知保留，不假确认 |
| SL-07 | 0/5/30 插件及1/8/30打开对象 | 一级导航不随安装数增长；固定、搜索、溢出和同名区分可用 |
| SL-08 | 1440→1100→800→390→变宽，字号放大 | 保留活动对象、输入、工具目标和返回路径；不缩字凑栏，不抢焦点 |
| SL-09 | 键盘/中文IME/读屏/触控 | 标签激活、菜单、Esc、区域切换与焦点归还有实际证据 |
| SL-10 | 布局预设应用、撤销、重开 | 不丢脏视图；偏好可恢复且按当前窗口钳制；不恢复旧许可/句柄 |
| SL-11 | 插件崩溃、停用、升级不兼容 | 其他区域可用、对象保留、替代/导出范围准确 |
| SL-12 | 阅读和非阅读普通作者包接入同一外壳 | 相同公开贡献/授权链，无第一方包 ID 特权分支；原生释放单独确认 |

建议原生骨架只先实现总览、导航范围、标签、一个支持区域和紧凑返回；采用四种 fixture 做结构验证后，再接两个真实普通包。自动化可核对身份/状态，仍需真实窗口的连续流程与用户走查。验收不通过时改结构，不用更多皮肤掩盖问题。
