# 软件分区与可替换组件

TSX 自带界面的扩展通路另见 [原生 UI 研究](../research/09-tsx-plugin-native-ui.md)：独立 Surface/VM 与受控原生槽位是待验证方案，普通 import 不构成隔离；已有组合资产提供者与完整 TSX 执行 profile 分别验收。

状态：v0.1 设计与架构工作基线；API0.3已实现首个想法输入角色的有界组合资产及临时挂载，通用区域组装和原生提供者替换尚未完成。关联 F-EXT-01/03/04/05/06、F-UX-01/02 及 [ADR 0028](../architecture/adr/0028-extensible-native-workspace.md)。目标是让功能增长、插件接入和组件替换保持一致体验。

## 分区先定义职责

```text
应用外壳
├─ 全局导航：工作区入口、搜索/命令入口、设置
├─ 当前工作区
│  ├─ 工作区工具栏：返回、当前对象、常用操作
│  ├─ leading：目录/过滤等局部导航（按需）
│  ├─ content：主内容，一个当前提供者
│  ├─ auxiliary：当前任务的辅助面板（按需）
│  ├─ context-actions：选区/对象的轻量动作
│  └─ object-status：与具体对象关联的状态
└─ 宿主受信界面：权限、信任、恢复与系统对话框
```

| 区域标识（设计名称） | 职责 | 插件使用方式 | 默认数量与行为 |
|---|---|---|---|
| `shell.workspaces` | 切换资料、笔记及其他已安装工作区 | 提供入口、标题、图标和路由；宿主统一排列与选择态 | 按工作流分组；安装不自动展开一排新面板 |
| `workspace.toolbar` | 当前对象身份与高频动作 | 贡献有语义的命令，按主/次/更多分组 | 标题、返回保持稳定，低频动作进入更多 |
| `workspace.leading` | 当前任务的局部导航 | 目录、筛选、书签等兼容提供者 | 默认折叠或恢复用户选择；窄窗按需打开 |
| `workspace.content` | 阅读、笔记等主内容 | 注册符合当前角色/格式的提供者 | 一个当前提供者；替换通过显式选择 |
| `workspace.auxiliary` | 当前引用、想法、信息等工具 | 注册面板提供者，接收有界当前对象上下文 | 默认关闭；一个主面板，多个工具通过面板内切换 |
| `workspace.context-actions` | 选区或对象操作 | 贡献动作与可用条件 | 短小、可见、可键盘访问；更多动作进入菜单 |
| `workspace.object-status` | 导入、保存、定位等反馈 | 提供类型化操作状态，由宿主统一呈现 | 靠近对象，不重复堆叠全局状态条 |

区域名与组件角色分开：区域回答“显示在哪里”，角色回答“能完成什么”。例如 `workspace.content` 可承载 `document.reader` 或 `note.editor`，由工作区声明；辅助区也可承载一个 `note.editor`，两者使用同一组件契约。

## 可替换性分三层

| 层次 | 可扩展内容 | 保持稳定的契约 |
|---|---|---|
| 视觉主题 | 用户选择的主题提供者可给出完整语义token集合 | 文字/背景配对、状态角色、基本可读性与宿主可信标识保持约束；安装不自动覆盖主题 |
| 功能组件 | 阅读器、编辑器、目录、引用列表等兼容提供者 | 角色、格式/版本、输入上下文、动作与数据保真；同一区域可更换实现 |
| 原生基础服务 | 控件适配、文本/文档引擎和平台渲染通过适配器演进 | 公开能力与资源协议不绑定NSH内部类型；普通功能插件不以任意FFI替换平台内核 |

公共组件层提供一致的行为与样式默认值，不把每个业务选择封死在单一实现里。先为实际需要的角色定义契约，避免为所有未来场景预建抽象。

## 四个层次的责任

1. **Host 外壳与原生适配器**：窗口、区域布局、主题、焦点、系统输入、受控 Surface、权限/信任及恢复。外壳从贡献目录组装入口，不按官方包 ID 写业务分支。
2. **工作区插件**：定义资料库、阅读、笔记等用户流程，选择兼容的区域和组件角色，消费公开能力。
3. **组件提供者**：实现某一语义角色，例如 PDF 阅读视图、Markdown 编辑器、目录、引用列表；可以来自其他普通插件。
4. **Core 与受控服务**：保存正式实体、来源、位置、笔记与引用；提供版本校验、事务、导出及原生文档处理。组件替换不迁移知识所有权。

Host 自身的授权/信任提示与安全来源标识保持可信呈现。组件可以替换功能表现，宿主继续掌握这些跨插件约束。

每个组件实例绑定工作区、区域、提供者安装/会话及mount世代，状态和动作不能串到其他实例。跨插件传递的对象上下文由Host验证并最小化；工作区不能替另一个提供者批准权限。可用性由Host按真实资源/权限重算；“已保存”依据Core回执，不采信插件自报状态。

## 组件怎样声明兼容

组合契约至少需要下列语义；表格不是当前 manifest/SDK 的已发布字段。

| 契约信息 | 用途 |
|---|---|
| 提供者身份 | 绑定已验证安装、贡献 ID、包版本和当前授权世代，不能只用一个字符串组件名 |
| 角色与契约版本 | 如文档阅读、笔记编辑、来源列表；按兼容范围匹配，未知必需版本拒绝 |
| 输入上下文 | vault、实体/文档版本、来源锚点、只读/编辑模式；来自可信解析，不靠插件自报 |
| 支持格式与能力 | PDF/EPUB、笔记格式、锚点版本、读写能力；缺少依赖时说明原因 |
| 事件与动作 | 打开、编辑、保存意图、定位请求、关闭请求；正式保存仍经 Core 回执确认 |
| 状态与恢复 | 可恢复的局部视图状态有独立版本；不序列化 Session、选区 lease、原生句柄或批准 |
| 尺寸与语义 | 最小可用尺寸、窄屏方式、焦点入口/出口、可访问名称和操作替代路径 |
| 资源与取消 | mount/job 身份、取消、世代、实际释放确认及限额；过期事件不得更新后继 |

功能插件可以通过公开原生组件与声明式布局组合界面。自定义阅读/绘制通过受控 Surface 接入，系统控件和文档引擎属于原生适配器。插件不直接获取 NSH 内部对象、数据库、平台指针或任意 FFI；新的自定义能力须进入版本化公开契约和隔离验证。

## 替换怎样发生

例子：把当前 Markdown 编辑器换成另一个兼容编辑器，或为 PDF 选择另一阅读提供者。

1. 从组件的更多菜单或设置中选择提供者。展示支持的格式、缺少的能力和新增权限；安装新插件不自动抢占默认组件。
2. 先核对格式/契约兼容与完整数据保留。富文本深度仍待产品决定；格式不兼容时保留当前编辑器，不静默转换或丢字段。
3. 有未保存输入时提供保存、保留并返回等清楚选择。可恢复草稿机制另行实现；没有真实落盘证据时只能说“未保存”，不能宣称退出后可恢复。
4. 宿主冻结旧实例输入，作废旧回调与选区，取消相关任务并开始释放。新提供者获得新实例与新句柄，按自身普通权限启用；不继承另一插件的许可。
5. 用 Core 的实体与来源锚点恢复内容和位置；只迁移兼容、非敏感的局部视图偏好。旧组件像素位置不作为永久定位。
6. 新组件失败时保留内容与恢复入口；原提供者仍可用且授权有效时可返回。资源尚未确认释放继续计入限额，不用换安装身份或删 map 腾出配额。

组件选择可按角色保存默认值，并允许当前资料临时覆盖。提供者消失时提示替代选择；停用/卸载后 Core 的已存引用、想法与原件仍能通过通用查看/导出恢复入口访问。

## 布局如何适应窗口

- 宽屏允许显式打开局部导航和辅助区；主内容拥有最小可读宽度。
- 中等窗口保留主内容和一个按需工具区；收起全局导航，工具不会互相挤成窄条。
- 窄窗进入单任务视图：阅读与编辑通过明确返回切换，同一实体/选段上下文保留。插件声明的最小尺寸不能突破宿主约束。
- 用户调过的分隔宽度可恢复为界面偏好；阅读进度、来源、笔记内容仍通过公开 Core 能力保存。

分区尺寸和展开状态由宿主统一治理。插件不能各自覆盖窗口，也不能在权限提示之上绘制内容。

初始宽度约束以逻辑点为单位：全局导航176/208/256（折叠56），局部导航180/224/280，辅助区280/336/440，分别为最小/默认/最大；主内容至少560并消费剩余空间。尺寸是待原生验证的工作初值，系统文字放大或窗口不足时切换布局，不强压组件。滚动属于各自区域，滚动条位于该区域边缘，分隔线只由一侧绘制。

内容/阅读位置归Core；展开、分隔宽度与组件选择属于版本化界面偏好；输入焦点、滚动视口、mount与未提交选区属于运行态。组件崩溃或不兼容时隔离对应区域，外壳保留当前对象与恢复入口，不能连带清除其他区域的输入。

## 当前实现边界

Host API0.2 已有阅读 Surface 与普通插件链路；API0.3已有想法输入组件的签名资产、角色校验、同Host精确草稿挂载及event续传，A的真实进程链已有证据。B段落算法与A→B→A正在验证；通用区域组装、原生提供者选择和完整替换事务尚未完成。落代码前补公开贡献点、协议版本、SDK作者样例与普通身份验证，不向0.2偷偷增加未知类型。现有 `apps` 仍只装配，原生适配器不承担阅读/笔记业务；不为设计文档预生成空 crate。

首次原生界面落地先使用内部slots/组件props承载真实阅读流程，不能据此宣称公开编辑器替换完成。跨插件想法编辑缺少精确Draft权限和修订契约，下一SDK切片见 [ADR 0028实施补充](../architecture/adr/0028-extensible-native-workspace.md) 和 [具体实施契约](../product/component-provider-contract.md)。本轮保留0.2语义，以明确的新API版本实现真实提供者替换。


## Agent 工作台角色扩展（C-13，设计）

沿用现有区域，任务列表占 leading、当前任务时间线占 content、代码差异/检查占 auxiliary；终端与电脑预览按需打开。候选角色为 `task.list`、`task.timeline`、`agent.session`、`changes.viewer`、`terminal.viewer`、`computer.preview`，详见 [工作台交互](agent-workbench.md)。这些不是已发布的 SDK 类型。替换视图不迁移后端会话，不停止任务；输入租约由 Host 作废/重授。切换后端另走显式交接；可信权限、输入控制和全局停止仍由宿主呈现。

想法编辑的待处理输入、逐段/全文方式、提供者替换与失败恢复见[具体交互](paragraph-editor.md)。本轮原生接入前的[上游核对](../../experiments/nsh-reader/evidence/paragraph-ui-upstream-check.json)记录发布、近期提交和Linux文档；保留现有固定版本，不以新提交说明代替本机验收。
