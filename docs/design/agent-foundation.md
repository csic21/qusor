## 基座提供什么

| 层次 | 职责 | 不变量 |
|---|---|---|
| 宿主与 Core | 空间、任务/会话身份、能力目录、区域组合、权限/信任、恢复；正式知识仍由 Core 持有 | 公开契约、输入所有权、版本、审计和数据归属不依赖某个 Agent 或界面 |
| Agent 接入插件 | 连接实际执行后端；映射事件、输入、工具请求、取消、恢复和成果 | 按实际能力协商；角色配置、模型 API 和完整 Agent 后端分别表达 |
| 工具/资源插件 | 文件、知识、搜索、服务连接、设备能力和可执行动作 | 安装、可发现、加入任务与取得资源授权是不同状态 |
| 交互/视图插件 | 对话、表单、阅读、表格、画布、编辑器、预览、差异与过程视图 | 以对象/版本和结构化结果驱动；可以替换；视图关闭不改变执行寿命 |
| 场景组合插件 | 指令/技能、建议工具、适用对象、初始交互和布局预设 | 通过同一公开 SDK 组合能力；不自带宿主特权，不自动授予资源/联网权限 |

以上是设计职责，不是五种已经发布的 manifest 类型；工具、场景与 Agent 接入可以由一个包贡献，也能来自不同包。第一方功能和第三方功能使用同一契约。

## 入口与工作空间

默认入口采用通用总览候选，展示当前空间、最近打开、用户固定功能和实际可继续的工作；随后可恢复用户最后工作。任务输入属于任务入口，不强制常驻首页。主导航承担工作组织、扩展与设置等通用目的；阅读、开发、自动化入口来自已安装贡献与用户固定项，不硬编码为必备一级导航。

用户可以直接描述目标，再选择 Agent、附件与能力；也可以从场景插件开始。输入进入任务草稿后，界面明确当前执行方、资源范围与连接状态。没有配置后端时保留草稿并提供连接入口，不能显示任务已开始。

同一空间可以承载多个任务；任务关联会话、资源、所用能力和成果。空间、任务、后端会话、运行尝试、视图实例分别持有身份。通用任务不强制存在代码项目或 Git 工作树；使用项目能力的任务才绑定其执行目标。

## 布局按交互需要组合

沿用 [组合区域](composition.md)，不把“区域”解释为永远可见的栏位。主内容可承载场景舞台、会话、成果或过程；局部导航、辅助区与输出按需要出现。对话也是可选择的视图，可居中、并置或收起。

| 场景示例 | 主交互与视图组合 | 由插件提供的能力 |
|---|---|---|
| 研究与知识整理 | 资料/证据与结论并置；对话可按需打开 | 来源、检索、引用、阅读、笔记、研究指令 |
| 内容创作 | 文稿或预览占主舞台，素材和版本按需出现 | 编辑器、提纲、媒体/排版预览、素材读取 |
| 事务/自动化 | 输入表单、步骤、待确认动作、实际执行记录 | 服务/设备连接、校验、执行动作、结果检查 |
| 项目开发 | 代码、差异、预览或会话按任务切换 | 项目文件、编辑器、Git、检查、终端及编程后端 |

这些用于验证组合能力，不表示所有示例都进入首版或已有独立功能包。不能只替换标题和图标来宣称场景适配；至少要实际改变主交互、成果呈现或工具组合。

布局预设只声明兼容角色、区域关系、显隐和主次。用户可调整并保存；Agent 可提出打开某个适用视图的建议。已允许的布局动作可局部执行，但不得替换正在输入的组件、丢草稿、抢焦点或覆盖宿主受信界面。布局变化不隐含资源授权或后端切换。

## 插件如何与 Agent 协同

1. 插件注册版本化贡献、适用对象、数据格式、所需能力及平台条件。
2. 宿主按任务、后端和环境求兼容集合；不可用项说明缺少哪项条件，不静默伪装可用。
3. 用户选择或场景预设建议启用能力，实际调用继续经过既有权限链路。
4. Agent 通过受控工具获得结构化结果/成果引用；宿主按角色和格式选择兼容视图，必要时提供文本/只读结果。
5. 人可以直接操作插件界面；会话收到明确关联的交互结果。UI 与 Agent 共用数据契约，不要求所有动作先转成聊天。
6. 正式知识修改继续经过 Core；文件、外部服务或设备副作用使用各自回执、冲突与未知状态处理。

结果视图按内容选择，不按后端品牌分叉页面。例如同一份带来源的研究成果可由不同兼容 Agent 产生，再由用户选择的引用/笔记视图呈现。自定义富交互保留普通插件边界与恢复路径。

## Agent 适配与切换

支持多后端的目标通过适配器逐个验证。结构化 Agent、仅有 CLI 的 Agent、远程 Agent 具有不同能力；不能用统一按钮承诺相同的恢复、工具拦截、附件或电脑控制能力。候选协议与兼容性依据见补充研究和 [ADR 0029](../architecture/adr/0029-local-agent-workbench.md)。

选择 Agent 配置不等于已有连接；更换模型也不等于更换执行后端。已有任务换后端时，新会话绑定与显式交接保留来源、已有成果、待处理状态及授权边界，不冒充继续同一原生会话。多 Agent 委派继续经宿主 broker，不通过两个执行方同时占有输入实现协作。

## 状态、关闭、卸载与手机

任务草稿、连接、排队、执行、等待输入、检查结果和成果整合分别表达。关闭视图只关闭展示；停止、撤权、停用执行提供者按真实控制与退出回执处理。执行未知不自动重放外部副作用。

场景停用后保留任务和正式成果；视图不可用时显示对象身份及替代/只读/导出路径。已收录知识仍由 Core 可读/引用/导出。私有插件草稿另按其格式与生命周期处理，不能承诺任意未发布格式均可通读。

手机按当前任务显示一个主视图，会话/成果/步骤可在同一任务内切换。场景在不同平台选择兼容交互与执行实现；六端目标与平台专属插件遵循 C-14/C-15，不要求每个工具在手机本地执行。

## 可观察验收

- AF-01：无开发场景时可创建/继续非编程任务；没有必备文件树、项目根或终端。
- AF-02：同一外壳切换研究、创作、事务与开发示例，主交互和视图组合确实改变；空间、任务身份和各自草稿不混淆。
- AF-03：一个 Agent 消费来自两个普通插件的能力；一个成果格式由两个兼容视图显示；第一方没有私有接入路径。
- AF-04：能力不支持、未授权、缺执行环境或未连接时如实显示，不伪造执行、恢复或完成。
- AF-05：替换/关闭视图保留任务、成果和未提交输入；后端切换使用新绑定；停用提供者如实停止/协调。
- AF-06：无界面工具、表单交互和富结果视图均可服务任务；未支持富界面时有清楚的能力边界或有损说明。
- AF-07：手机和字号放大时保留任务切换、输入和宿主控制入口；插件平台资格分别实测。

本轮样稿只覆盖 AF-01/02 的可见结构与局部选择/草稿交互，其他项是后续真实 SDK/原生/后端验收，不能由静态示例宣布通过。
