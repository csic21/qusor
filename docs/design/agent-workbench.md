# Agent 工作台：UI、交互与完整体验

日期：2026-11-08。状态：v0.1 可评审设计，未实现、未做用户测试。关联 C-13、F-AGENT-01–05、F-UX-01/02。采用 [设计基础](foundations.md) 与 [组件分区](composition.md)；产品行为见 [功能规格](../product/agent-workbench.md)，系统边界见 [ADR 0029](../architecture/adr/0029-local-agent-workbench.md)。

2026-11-09增量：用户希望将日常编程放在 QUSOR，新增 [开发工作区](development-workspace.md)。下文任务时间线是任务优先视图；代码优先视图将文件/差异/预览放在主区、当前 Agent 放辅助区，保留同一任务和执行身份。文件冲突、检查/Git、编辑提供者与移动流程按新规格补验。

## 体验目标

用户应随时知道：正在操作哪台电脑和哪个项目；谁正在做什么；哪里需要自己；已经改变了什么；怎样接管或停止。多 Agent 的复杂性放在可展开的任务关系与执行记录中。阅读依旧安静，任务工作台允许更高密度，但不能把整个产品变成终端墙。

阅读、思考、执行是同一应用的不同工作状态，保留统一导航、搜索、主题和返回路径。阅读选区可显式带引用创建任务；任务成果可以审核后保存为笔记。切换状态不扩大资料范围，也不自动开启屏幕采集。

## 信息架构

全局导航继续通过插件贡献，增加“任务”入口。项目是任务的上下文，任务是用户目标，Agent 会话是执行渠道；终端只是可选工具。相同会话可以从多个视图查看，但仅有一个输入所有者。

| 层级 | 用户看到什么 | 设计约束 |
|---|---|---|
| 工作台总览 | 最近项目、进行中、待你处理、已完成 | 待处理优先，保留安静的完成收件箱；没有任务时只给新建/接入入口 |
| 项目 | 机器、目录、分支、已有修改、任务列表 | 项目不同只显示其任务；设备与目录不可藏到设置 |
| 任务 | 用户目标、负责人、进展、子任务、成果 | 主视图默认摘要和时间线，不默认展开全部工具输出 |
| 会话 | 执行方、实际模型、历史、输入所有权 | 切换后端称交接，保留原会话，不伪装成同一上下文 |
| 检查/终端/电脑 | 代码差异、检查结果、原始输出或控制预览 | 明确是否只读、谁在输入、电脑操作是否正在进行 |

## 桌面主视图

[任务执行设计稿](assets/agent-workbench.svg) 为目标界面，内容为自拟场景和模拟状态，不是运行截图。

布局沿用现有区域：全局导航 → 项目任务列表（leading）→ 当前任务（content）→ 按需成果/差异（auxiliary）。宽屏可以打开差异检查；中等窗口收起导航并只保留一个辅助区；窄窗在任务、子任务、差异间单页切换，明确返回，不把四列压成窄条。

顶栏长期展示项目、设备及分支。任务标题下显示负责人、模型、运行时间与当前动作，状态要有文字。子任务卡片包含“委派给谁、为什么、当前状态、可检查结果”；默认只展开需关注的分支，深层树可切列表。状态变化不自动抢焦点或切换当前任务。

底部输入属于当前选中任务，发送按钮旁始终明确接收方。输入可以是补充目标、回答问题或交接摘要；执行中能否直接 steering 由后端能力决定，不支持时显示排队或等待，不能悄悄丢消息。模型选择显示后端和 provider/model 两级，实际回执不一致时显式提示。

## 关键流程和动作

### 建立任务

默认只需要项目、目标和负责人三项。高级项按需展开：模型、允许操作、资料附件、预算和委派策略。上次项目和策略可以恢复，但要重新显示当前设备与目录；任务不能因恢复偏好自动执行。已有修改靠近启动动作提示，提供独立工作树等合适方案。

首次接入后端显示可用状态、版本、登录状况及已验证能力。用户可以复用该后端自己的登录；QUSOR 不宣称订阅可跨模型/后端通用，也不自动迁移密钥。发现已有会话先列元数据，用户选择后才读取/继续；能识别的项目与原生 ID 用于防重复绑定。

### 委派与协作

用户可说“让 Codex 实现，用 OpenCode 的某模型审查”。呈现为一个父任务和两个有顺序/依赖的子任务，不强制用户手动开两个终端。委派后显示输入摘要、资料来源、执行方和权限范围。后端缺失或指定模型不可用时给安装/配置或改选入口，不静默替换。

持续运行只显示当前动作和重要变化，日志折叠且有大小上限、搜索与导出。一个 Agent 声称完成时仍显示实际检查状态；审查结论与运行测试结果分开。多 Agent 得出冲突结论，保留双方与对应证据，不把最后一个回复当最终事实。

### 待你处理

问题、扩权请求、交接与成果检查进入同一个可筛选队列，标明任务和阻塞范围。普通提问用内联卡片；真正权限决定由宿主受信界面呈现，插件无法仿造。可以打开上下文再决定，也可批量处理相同范围的适合事项；不把普通命令都变成确认弹窗。

区分“回答问题”“允许本次操作”“调整项目授权”和“接受代码成果”。持续许可显示有效项目、能力和期限，扩大范围重新决定。已有许可不能通过换 Agent 放大。屏幕采集/输入控制的启用单独说明目的、目标应用及出站范围。

### 检查与完成

辅助面板有“变更 / 检查 / 输出”三个入口，一个当前主面板。变更显示基线、文件、diff、是否已写入当前项目或仅在隔离工作树。接受成果不是第一次执行写文件：界面明确写入位置，整合时再核对用户修改和冲突。

任务完成卡区分“已修改文件”“已执行检查”“尚未整合”“已提交/合并”，每项指向真实记录。保存成知识笔记需要明确来源与 AI 标记；用户可以批量审核，但不能由执行方假造批准。支持继续追问、交接、复制成果和打开文件，不自动部署。

### 接管与停止

会话工具栏提供“接管输入”和“停止任务”，终端焦点不是取得控制权。接管成功后显示“你正在控制”；Agent 自动输入暂停，交还后才恢复。关闭终端仅关闭视图，任务仍在运行这一事实就地说明。

“停止任务”展开影响范围并停止该任务及所属执行子树；独立任务不受影响。显示“正在停止”，直到确认退出；未知时给查看进程/恢复入口。电脑控制状态条与全局“停止电脑操作”保持可达，用户切换窗口/使用输入设备时按控制策略暂停，不能误向另一个应用打字。

## 状态与文案

| 状态 | 示例文案 | 可操作恢复 |
|---|---|---|
| 空工作台 | 新建任务，或接入已有 Agent | 选择项目、配置后端、导入所选会话 |
| 等待资源 | 等待项目写入权；当前由“修复测试”使用 | 查看占用任务、改用独立工作树、取消 |
| 运行 | OpenCode 正在审查 3 个文件 | 看当前动作、补充说明、接管、停止 |
| 需要输入 | Codex 需要你确认接口行为 | 看上下文、回答、稍后处理 |
| 网络失败 | 模型连接中断。已发生的文件修改可检查。 | 查看修改、重试、交接 |
| 部分完成 | 实现完成，审查任务失败 | 检查已有成果、仅重试失败步骤 |
| 停止未确认 | 已请求停止，仍在核对执行状态 | 禁止重复启动有副作用动作、查看详情 |
| 重启恢复 | 正在核对原会话与项目修改 | 等待核对、查看只读历史；未知时人工检查 |
| 提供者移除 | 历史可查看；继续任务需要该后端或交接 | 选择后端、导出、重新接入 |
| 输入控制中 | QUSOR 正在操作：测试应用 | 暂停、接管、停止；界面切走仍保留宿主指示 |

取消、停止、关闭视图、撤回文件和撤销知识修改使用不同名称与结果。日志文字“done”、终端退出、通过测试和用户接受互不替代。

## 视觉、键盘与无障碍

沿用暖中性外壳、统一文字角色和少量绿色强调色。任务密度高于阅读，但正常文本不小于既有 UI 基线。执行方身份、状态、范围和警告用文字加图标表达，颜色只作辅助。运行图标遵循减少动效设置；不持续闪动终端或整页自动滚到最新。

列表选择不等于启动；`Enter` 在合适上下文打开任务。输入框中文 composition 期间不发送，换行/发送提供可见说明并尊重用户设置。`Esc` 退出临时浮层或返回，不充当全局杀进程。终端使用清楚的焦点边框，应用快捷键与终端按键的路由可发现；具体停止快捷键在冲突验证后确定，不把未验证组合写成承诺。

事件流默认合并播报阶段变化、阻塞和完成，不逐 token 触发读屏。代码 diff 有文件列表、修改摘要与可导航的逐块文本替代；任务关系也有线性列表。焦点回到触发入口，错误不清输入，字体放大优先切换布局。

## 组件角色与替换

候选角色：`task.list`、`task.timeline`、`agent.session`、`changes.viewer`、`terminal.viewer`、`computer.preview`。它们是设计名，尚非 SDK 类型。工作台插件组合角色，Host 管理尺寸、焦点、可信授权和输入租约。

更换会话或终端组件仅替换视图，保留任务和后端绑定；旧视图输入租约失效，确认释放后再授予新实例。更换执行后端是独立交接操作，必须展示新模型、范围和摘要。新组件不能读取未被当前工作区授权的日志，也不继承旧插件的电脑权限。

## 原生实现验证与体验验收

优先原生任务列表、文本输入、树/列表和差异视图。终端需要 PTY 仿真、ANSI/VT、滚屏、选择/复制、宽字符、中文组合输入和键盘路由；NSH TUI 后端并不证明这些能力。图形电脑控制另验平台可访问性、屏幕采集和输入服务；不先默认 WebView 方案。上游核对记录及固定提交见 ADR0029。

首次原型分别完成“建任务→委派→回复→查看差异→接管→停止”和“关视图→重开→核对任务→交接”的全流程。原型可使用明确标注的合成事件检验布局，不能据此声称 Agent 已接通；真实阶段使用 AW 场景验收。

拟定可用性门槛：未受讲解的用户能在 10 秒内判断设备/项目/负责人/是否需介入；能无快捷键完成关键流程；取消后不误以为文件回滚；交接后不误以为全部历史无损迁移。记录任务成功、停顿、错误控制对象、误发送、恢复结果与主观负担。数值为待测试目标，目前没有成绩。1440/1100/800/390 代表宽度、系统字号、中文 IME、读屏与减少动效逐项验证；移动端先设计查看/回复/远程接管的可能路径，不承诺在手机本地运行桌面 CLI，远程连接也未默认开启。
