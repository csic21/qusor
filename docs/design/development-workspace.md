## 一个项目里的连续工作

目标流程：打开项目 → 浏览/搜索代码 → 手动编辑或选段交给 Agent → 检查实际变更 → 运行和调试 → 查看预览 → 审查与整合 → 提交 → 保留任务记录及可引用的项目知识。

“项目”绑定设备、实际根目录和仓库/工作树身份；“任务”承载目标；“会话”承载一次后端上下文；“文件”保留在项目文件系统中。编辑器、终端和聊天是可切换视图。切换视图不切换执行对象，不丢未保存输入，不停止已运行任务。

阅读、笔记、开发共享外壳与来源规则。项目设计文档、代码文件和阅读来源可在同一视图组打开，但附件共享须显式选择；打开开发工作区不会把整个知识库加入 Agent 上下文。

## 桌面区域

```text
全局工作区栏：资料 / 笔记 / 开发 / 其他已固定入口
┌──────────────── 项目 · 设备 · 工作树/分支 · 运行目标 ────────────────┐
│ 局部导航             主内容：对象标签 / 可选视图组      当前 Agent    │
│ 文件 / 搜索 / 任务    代码、文档、差异、应用预览        会话与上下文  │
│ 变更                 当前文件的动作                  待处理与委派  │
│                      ──────────────────────────────────────────────│
│                      终端 / 问题 / 检查 / 运行输出（按需）           │
└──────────────── 当前对象、保存与运行状态 ────────────────────────────┘
```

| 区域 | 内容与规则 |
|---|---|
| 全局入口 | 开发是完整工作区；安装新的后端不会给每个 Agent 增加一个全局入口 |
| 工作区顶栏 | 项目、设备、分支/工作树持续可辨；运行配置、启动/停止靠近运行目标 |
| `workspace.leading` | 文件树、项目搜索、任务、变更共享一个导航位置，按任务切换；大量文件采用有界列表 |
| `workspace.content` | 对象标签和可选视图组；每个视图组一个当前提供者，可承载代码、diff、文档、预览或任务时间线 |
| `workspace.auxiliary` | 一个当前 Agent 面板，显示后端、实际模型、会话、执行目标和附件；按需收起或提升为主视图 |
| `workspace.output` | 终端、问题、检查与运行输出；区域设计新增项，尚非公开 SDK 名称；运行不中断地收起 |
| 上下文动作 | 将当前文件/选区、诊断或差异加入任务；动作明确当前项目和接收任务 |

区域宽度由主内容可用性、编辑字号和系统缩放决定；空间不足时先收起局部导航，再将 Agent 变为独立任务页。双栏同时满足双方最小可用尺寸时才展开。阅读仍遵循安静模式；开发可以保留用户明确固定的 Agent 或终端。

代码优先、任务优先、审查、预览是同一工作区的视图状态，保留项目/工作树和任务绑定。用户可以固定一个 Agent 面板；异步任务事件不能自动替换当前编辑文件或滚动位置。

## 手动编辑与 Agent 协作

1. 打开文件时展示其项目相对路径、工作树和保存状态。选区加入任务时绑定文件版本、选区范围及精确文本快照。未保存内容先明确为“编辑器内容”，不把它当成磁盘文件已更新。
2. Agent 输入区显示实际接收方及附件。每条附件可查看、移除，并区分项目文件、未保存选区、诊断、运行输出、知识引用。后端自己扫描项目的范围按其实际执行约束说明，附件列表不宣称穷尽后端能访问的文件。
3. 后端不能接收结构化临时内容时，将选区转为显式文本附件，或要求用户选择保存后继续；不静默保存未提交输入。
4. 单个直接编辑任务可使用用户选择的当前工作树。并行写任务优先独立 Git worktree；非 Git 项目采用受控写任务串行。用户仍可能通过其他进程修改文件，Host 需要监视并重新核对。
5. 文件有未保存编辑时，若 Agent 或外部工具改了磁盘版本，显示“磁盘内容已变化”，提供比较、合并或保留输入后另存。保存必须核对打开/上次保存时的磁盘版本，不能把旧缓冲区直接覆盖新文件。
6. 相同路径在不同工作树中是不同编辑对象。任务产物打开其实际工作树文件，整合前保留修改位置和基线。把 Agent 输入焦点交给用户与修改源代码是两个动作。
7. 关闭编辑器先处理未保存内容；关闭会话视图保留任务执行事实。重新打开可恢复已验证落盘的视图状态，跨重启缓冲区恢复另设门槛，不能从会话内保留推导已持久草稿。

## 运行、预览与检查

运行入口先显示命令/目标、设备、工作树和配置。运行产生的服务、终端会话与子进程归执行记录，按真实退出事实管理；切走编辑页仍可找到对应输出和停止入口。

诊断点击可打开具体文件和行列，记录对应文件版本；已变更时提示过期或重新检查。检查区区分未运行、运行中、通过、失败、中断和结果未知。Agent 自述与测试进程回执分别呈现。

应用预览打开经核对的本地开发服务，并绑定任务/设备/端口/实例；端口被其他服务占用时不能展示错误项目。网页目标需要实际网页渲染，这是预览对象本身的能力；开发外壳、编辑器和终端继续原生优先。调试需独立的断点、调用栈、变量和执行控制契约，不把终端打印称为调试器。

Git 视图区分工作区修改、暂存、提交、推送、合并和部署。整合复核基线和用户修改，冲突保留双方；不自动 reset/stash。任务完成不会隐式触发推送或部署。

## 后端接入和委派

后端选择、配置和会话恢复沿用 [既有流程](agent-workbench.md)。优先协议连接，其次结构化 headless 事件；PTY 仅作兼容，不能靠画面或文本“done”判定业务完成。

推荐先验证 Codex App Server 的 thread/turn/事件/批准与恢复，再验证 OpenCode server/SDK 的 session、事件、显式模型和取消。dsh 沿项目已实测的 scoped 包 headless 路径验证有界小任务；实际持续会话/取消/恢复能力核实后才开放。模型 API、完整 Agent、MCP 工具使用不同配置层。

委派以任务包传入目标、输入版本、允许修改范围、检查方式和成果位置。示例：“Codex 实现 → dsh 做隔离文案或小修复 → OpenCode 审查”。角色和默认后端由用户配置；这不是对各后端能力/成本的固定排名。对子任务逐项核对可用能力，未支持的模型或恢复方式明确不可选。

## 功能包与受控服务

以下均为规划职责/角色，尚非已发布 manifest、SDK 或已创建目录。

| 功能包职责 | 组件角色候选 | 宿主受控服务 |
|---|---|---|
| `plugins/development-workspace/` 组合开发流程 | `project.navigator`、`project.search`、视图布局 | 项目注册、资源/会话绑定、版本化界面偏好 |
| 代码编辑提供者 | `code.editor`、`code.diff` | 项目文件版本、缓冲区/磁盘冲突、受控原生文本输入；语言服务另接 |
| Git/运行/检查流程提供者 | `changes.viewer`、`diagnostics.list`、`run.configuration` | 文件监视、仓库/工作树操作、进程监督、LSP/DAP 连接及检查记录 |
| 终端/应用预览提供者 | `terminal.viewer`、`application.preview` | PTY/终端仿真、输入租约、本地服务定位及适用预览引擎 |
| 既有 Agent 工作台/后端/调度插件 | `task.list`、`task.timeline`、`agent.session` | 任务/委派 broker、后端协议、有效授权、事件与恢复 |

独立第一方插件通过与第三方相同的版本化接口运行；底层原生资源和平台服务放 adapters，纯协议/状态机/端口放 crates，apps 只装配。Core 保存知识实体和引用，项目代码仍在文件系统；选中的代码作为知识证据时才经过明确捕获及 Core 用例。调试/预览的联网、进程和端口资源按实际能力授权。

## 手机、平板与 Web

手机的开发项目采用“文件/任务列表 → 当前对象 → 编辑/差异/输出”的导航栈，同一时间一个主要任务。可查看代码、做适合触控的小修改、回复任务和核对结果；持续桌面级编辑可在平板/宽屏展开视图组。项目身份、来源和权限在各端保持一致。

手机本地可执行什么取决于已验证平台服务与后端。未来连接其他设备时必须明确执行设备和连接状态，另行配置与授权；本设计不自动开启远程控制，不承诺在手机内运行桌面 CLI。Web 同样不能由浏览器文件访问推导已有本机执行能力。
